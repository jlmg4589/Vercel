# 2. Reducción del número de servicios

Un primer paso para bastionar un sistema es **controlar que los servicios ofrecidos son exactamente los que queremos ofrecer** y que no hay otros servicios activos que no tengamos controlados. Cada servicio innecesario es una posible puerta de entrada si en algún momento aparece una vulnerabilidad en él.

- **Como servidores:** garantizar que los recursos ofrecidos tienen la confidencialidad necesaria y que no pueden ser usados por terceros no deseados.
- **Como clientes:** asegurar los mecanismos de autenticación (que nos conectamos al servidor correcto y no hay suplantación de servicios o servidores, algo difícil de detectar) y no poner en peligro a nuestros usuarios por usar servicios inseguros.

> [!important] Servicios inseguros
> Hay que evitar los servicios que **no cifran datos ni contraseñas**: *ftp*, *telnet*, correo no seguro, y las órdenes remotas clásicas de UNIX (*rlogin*, **rsh**, *rcp*). En su lugar se utilizan conexiones cifradas como **SSH** y **SSL/TLS**. Ver [[Bastionado de redes y sistemas/Unidad 7 Configuración de sistemas informáticos/Apuntes/5. Securización de la administración remota\|5. Securización de la administración remota]] y [[Bastionado de redes y sistemas/Unidad 4 Diseño de redes seguras/Apuntes/9. Protocolos de red seguros\|9. Protocolos de red seguros]].

| Servicio inseguro | Problema | Alternativa segura |
| :-: | --- | :-: |
| Telnet (23/TCP) | Transmite todo, incluidas las credenciales, en texto claro | SSH |
| rsh / rlogin / rcp | Órdenes remotas sin cifrado | SSH / scp |
| FTP | Credenciales y datos sin cifrar | SFTP (SSH) |
| TFTP (69/UDP) | Transferencia de ficheros sin autenticación ni cifrado (actualizado, fuente: [RFC 1350](https://www.rfc-editor.org/rfc/rfc1350)) | SFTP / scp |

> [!info] Contenido complementario (fuente externa)
> **TFTP** (*Trivial File Transfer Protocol*) es un protocolo mínimo sobre **UDP/69** que solo permite leer y escribir ficheros: **no tiene autenticación ni cifrado**, así que cualquiera que alcance el servidor puede descargar (o subir, si se permite escritura) ficheros. Su propia especificación indica que no incluye mecanismos de autenticación. Se sigue usando para arranque por red (PXE) y firmware/configuración de dispositivos de red; si es imprescindible, limitarlo a una red de gestión aislada, en solo lectura y con un directorio raíz restringido; en otro caso, desinstalarlo.
> Fuente: [RFC 1350 – The TFTP Protocol (Revision 2)](https://www.rfc-editor.org/rfc/rfc1350).

## 2.1 Análisis de servicios en GNU/Linux

### 2.1.1 El proceso init

En GNU/Linux, **init** es el primer proceso que inicia el *kernel* durante el arranque. Es un *daemon* que se ejecuta en segundo plano mientras el sistema está encendido y es el **padre de todos los demás servicios**. Si init (o systemd) no arranca, el sistema no puede arrancar.

Sistemas init más utilizados:

1. **System V (SysV):** uno de los primeros y más tradicionales sistemas init de Unix.
2. **Upstart:** reemplazo de SysV usado por openSUSE 11, WebOS o Chrome OS; la tendencia actual favorece a systemd por su mejor rendimiento.
3. **systemd:** el sistema init adoptado por la mayoría de distribuciones (Debian, Ubuntu, Fedora, Arch Linux…). Permite arrancar tareas en paralelo y reduce la sobrecarga de la *shell*.

> [!note]
> Algunas distribuciones (por ejemplo, Ubuntu Server 20.04 LTS) mantienen SysV y systemd a la vez por retrocompatibilidad.

En systemd, los objetos de control se llaman **unidades** y se gestionan con la herramienta **`systemctl`**.

### 2.1.2 Gestión de servicios con systemctl

Tomando como ejemplo el servicio `cron` (tareas programadas):

```bash
systemctl status              # todos los servicios cargados (salida muy extensa)
systemctl status cron         # estado de un servicio concreto
systemctl start cron          # iniciar
systemctl stop cron           # detener (no cambia su comportamiento en el siguiente arranque)
systemctl restart cron        # parar + iniciar
systemctl reload cron         # releer la configuración sin parar el servicio
systemctl is-enabled cron     # ¿se inicia en el arranque?
systemctl enable cron         # habilitar en el arranque
systemctl disable cron        # deshabilitar en el arranque
```

- **restart:** parada + inicio.
- **reload:** el servicio sigue corriendo y vuelve a leer sus ficheros de configuración.

> [!warning]
> `enable`/`disable` **no** inician ni detienen el servicio en ese momento; solo fijan su comportamiento a partir del siguiente arranque.

### 2.1.3 Listar los servicios del sistema

Desde el punto de vista de la ciberseguridad, reducir al máximo los servicios no utilizados evita que usuarios malintencionados aprovechen vulnerabilidades. Son **especialmente peligrosos los servicios que escuchan al exterior a través de *sockets*** (IP y puerto), porque ofrecen una vía directa al proceso.

**System V**

```bash
service --status-all            # servicios y su estado
service nombre-servicio status  # estado de un servicio
chkconfig --list                # servicios habilitados en el arranque (puede requerir instalar el paquete)
```

**systemd**

```bash
systemctl                                   # unidades en ejecución
systemctl list-unit-files --type service    # unidades de servicio según su estado
systemctl status <servicio>                 # estado de un servicio concreto
systemctl list-unit-files | grep enabled    # servicios habilitados en el arranque
```

Columnas de la salida de `systemctl`:

| Columna | Significado |
| :-: | --- |
| UNIT | Nombre de la unidad |
| LOAD | Si la unidad está cargada en memoria |
| ACTIVE | Si la unidad está activa |
| SUB | Si la unidad está funcionando |
| DESCRIPTION | Breve descripción |

### 2.1.4 Localizar servicios expuestos en red

Para saber qué servicios están escuchando en la red se usan las herramientas de *sockets*:

```bash
ss -tulpn        # -t TCP, -u UDP, -l a la escucha, -p proceso/PID, -n sin resolver nombres
netstat -ntap    # equivalente clásico (paquete net-tools, obsoleto)
nmap 192.168.0.50  # comprobar desde fuera qué puertos quedan abiertos
```

> [!tip]
> `netstat`, `ifconfig`, `route` y `arp` (paquete *net-tools*) se consideran obsoletos; sus equivalentes modernos son `ss` e `ip`.

## 2.2 Reducción de servicios en GNU/Linux

### 2.2.1 Deshabilitar permanentemente un servicio

```bash
sudo systemctl disable bluetooth.service
```

systemd borra el enlace simbólico que se creó al habilitarlo (en el ejemplo, `/etc/systemd/system/dbus-org.bluez.service`) y el servicio ya no se activa en el arranque.

> [!warning]
> - Aunque esté deshabilitado, **un administrador puede iniciarlo manualmente**.
> - Hay que tener precaución: deshabilitar un servicio sin saber qué hace puede causar problemas graves.

### 2.2.2 Enmascarar y desenmascarar un servicio

Si además queremos que **no se pueda iniciar ni manual ni automáticamente**, se **enmascara**:

```bash
sudo systemctl mask bluetooth.service     # nadie podrá iniciarlo
sudo systemctl unmask bluetooth.service   # revertir
```

### 2.2.3 Desinstalar lo que no se usa

La opción más segura es eliminar el paquete que ofrece el servicio. Por ejemplo, para servidores de acceso remoto inseguros en Debian/Ubuntu (los nombres de paquete varían según la distribución: compruébalos con `dpkg -l | grep -E 'telnet|rsh|tftp'`):

```bash
sudo apt purge telnetd rsh-server tftpd-hpa
```

## 2.3 Control de acceso a servicios: TCP Wrappers y xinetd

### 2.3.1 /etc/nologin

Si existe el fichero `/etc/nologin`, **nadie excepto root puede iniciar sesión**; en su lugar se muestra el contenido del fichero.

### 2.3.2 TCP Wrappers

Sistema para conceder o denegar el acceso a servicios de red según reglas de dos ficheros:

- **`/etc/hosts.allow`:** hosts que tienen **permitido** el acceso.
- **`/etc/hosts.deny`:** hosts que tienen **denegado** el acceso.

Las reglas tienen el formato `lista_servicios : lista_host`:

- **lista_servicios:** uno o más servicios de `/etc/services`.
- **lista_host:** nombres, direcciones IP o redes completas.
- Se admiten comodines como `ALL`, `LOCAL`, etc.

```text
# /etc/hosts.allow
sshd: 192.168.1.
# /etc/hosts.deny
ALL: ALL
```

Para saber si un servicio usa TCP Wrappers:

```bash
strings /usr/sbin/sshd | grep hosts_access   # buscar la directiva hosts_access
ldd /usr/sbin/sshd | grep libwrap            # comprobar si enlaza la librería libwrap
```

### 2.3.3 xinetd

Mecanismo de control de servicios que amplía a su antecesor **inetd**. Permite habilitar servicios según el **horario**, el **origen** (como TCP Wrappers), la **interfaz**, etc. Su configuración está en `/etc/xinetd.conf`:

```text
defaults
{
  log_on_success = HOST PID
  log_on_failure = HOST USERID PID
  only_from      = 192.168.1.0/24
  no_access      = .empresa.org
}

service ftp
{
  disabled       = no
  socket_type    = stream
  user           = root
  server         = /usr/sbin/in.ftpd
  instances      = 4
  access_times   = 7:00-12:30 13:30-21:00
  nice           = 10
  log_on_success += DURATION
}
```

> [!tip]
> Un servicio gestionado por xinetd se desactiva poniendo `disabled = yes` en su bloque.

## 2.4 Reducción de servicios en Windows 10

Windows incluye multitud de servicios para adaptarse a cualquier situación, pero no siempre son necesarios.

> [!important]
> Antes de cualquier cambio, **crear un punto de restauración** («Crear punto de restauración» en la búsqueda → seleccionar unidad → *Crear*).

Los servicios están en **Administración de equipos → Servicios y Aplicaciones**, con nombre, descripción, estado y **tipo de inicio**:

1. **Automático:** se inicia con cada arranque.
2. **Automático (inicio retrasado):** se inicia cuando el sistema ya ha cargado.
3. **Manual:** se inicia cuando una aplicación lo necesita.
4. **Manual (desencadenar inicio):** solo se inicia si se da el evento desencadenante (la fuente indica «si no hay demasiados servicios en ejecución»).
5. **Deshabilitado:** no se puede iniciar.

Se cambia con clic derecho sobre el servicio → Propiedades → Tipo de inicio.

### 2.4.1 Servicios que se aconseja deshabilitar

| Servicio | Motivo | Configuración recomendada |
| --- | --- | :-: |
| Administrador de mapas descargados | Solo si se usa la app Mapas | Manual |
| Fax | Casi nunca necesario | Deshabilitado |
| Enrutamiento de mensajes de inserción WAP (*dmwappushservice*) | Envía telemetría a Microsoft | Deshabilitado |
| Panel de escritura a mano y teclado táctil | Solo con hardware compatible | Deshabilitado |
| Seguimiento de diagnósticos | Telemetría | Deshabilitado |
| Asistente para la compatibilidad de programas | Solo con software antiguo | Manual |
| Servicio biométrico de Windows | Sin hardware biométrico | Deshabilitado |
| Autenticación natural | Sin lector de huellas/biometría | Deshabilitado |
| Cola de impresión | Solo con impresora | Manual |

Estos servicios, poco usados, pueden ser una vía de entrada si se descubren fallos de seguridad en ellos.

### 2.4.2 Msconfig

`msconfig` permite controlar de forma sencilla los programas y servicios que arrancan con Windows:

- **Pestaña General:** inicio *Normal*, *Con diagnóstico* (solo servicios básicos) o *Selectivo*.
- **Pestaña Servicios:** desmarcando un servicio, no se inicia. La casilla *Ocultar todos los servicios de Microsoft* muestra solo los instalados por terceros.
- **Inicio de Windows:** habilitar/deshabilitar aplicaciones que arrancan con el sistema; conviene revisarlas porque ralentizan el inicio y **muchos virus se introducen en el inicio**.

> [!warning] El hardening no debe entorpecer al sistema
> Solo se deshabilita lo que no aporta funcionalidad: si el equipo usa impresora, wifi y correo, no se deben desactivar la cola de impresión, el servicio de redes inalámbricas ni bloquear SMTP/POP. Ver [[Bastionado de redes y sistemas/Unidad 7 Configuración de sistemas informáticos/Apuntes/3. Hardening de procesos\|3. Hardening de procesos]].

> [!example] Actividad 1
> En una máquina virtual Debian/Ubuntu: lista los servicios habilitados en el arranque, identifica los que escuchan en red con `ss -tulpn`, deshabilita uno innecesario y enmascara otro. Comprueba que el enmascarado no puede iniciarse manualmente.
