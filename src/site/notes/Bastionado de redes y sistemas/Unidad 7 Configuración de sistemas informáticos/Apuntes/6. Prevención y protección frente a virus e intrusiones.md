# 6. Prevención y protección frente a virus e intrusiones

## 6.1 Software malicioso

El ***malware*** (*malicious software*) es cualquier programa o fragmento que genera algún problema en el sistema sin conocimiento de su propietario.

| Tipo | Descripción |
| :-: | --- |
| Virus | Código insertado en un ejecutable huésped que se replica en otros programas |
| Gusano | Se ejecuta y propaga por sí mismo por la red, aprovechando *bugs* |
| Bomba lógica | Código latente que se activa en determinadas circunstancias |
| Troyano | Programa aparentemente inofensivo con código oculto |
| Puerta trasera (*backdoor*) | Atajo de acceso dejado por el programador |
| *Rootkit* | Troyano que oculta puertas traseras con máximos privilegios |
| *Spyware* / *Adware* | Recoge información del usuario / muestra publicidad |
| Conejo o bacteria | Se reproduce hasta agotar los recursos (DoS) |
| *Keylogger* | Registra las pulsaciones de teclado (y a veces capturas) |
| *Hijacker* | Modifica la página de inicio y redirige las búsquedas |
| *Joke* / *Hoax* | Broma que simula infección / bulo sobre virus falsos |
| *Exploit* | Código que aprovecha una vulnerabilidad |
| *Rogueware* | Falso antivirus que cobra por una falsa desinfección |
| *Ransomware* | Cifra ficheros y pide un rescate |
| *Bots* | Equipos zombis que forman una *botnet* controlada remotamente |

**Métodos de infección:** vulnerabilidades del SO, páginas web con código activo, documentos con **macros**, ejecutables camuflados (doble extensión, iconos falsos), ingeniería social, dispositivos extraíbles con ejecución automática, ficheros de datos que explotan vulnerabilidades de programas comunes (p. ej. clientes de correo) y *cookies* maliciosas.

**Tras ejecutarse**, el malware intenta residir en RAM, obtener **persistencia** (ficheros de inicio, registro), instalarse en el MBR/sector de arranque, autocifrarse o cambiar de forma, atacar al antivirus, conectar con servidores externos y reenviarse a los contactos.

## 6.2 Herramientas antimalware

Más del 99 % del malware se diseña para Windows, aunque existe para macOS, Linux, Android e iOS. Las herramientas antimalware se clasifican en **antivirus**, **antispyware** y **herramientas de bloqueo**.

### 6.2.1 Antivirus

Previenen, detectan y eliminan virus usando **bases de datos de firmas** y **técnicas heurísticas**. Su base fundamental es la **actualización** de la base de datos.

- **Según la acción:** detectores, detectores y eliminadores, y protectores (preventivos o inmunizadores, residentes en memoria).
- **Según el modo de ejecución:**
  - **De escritorio:** residentes; se recomienda **uno solo** por equipo (incompatibilidades).
  - **En línea:** detectan/eliminan pero no protegen.
  - **De ficheros en línea:** analizan ficheros enviados con varios motores.
  - **Live CD/USB:** arrancan el equipo para analizarlo cuando el virus impide arrancar o desinfectar.
  - **Portátiles:** no se instalan; se llevan en USB.
  - **EDR** (*Endpoint Detection and Response*): antivirus + monitorización + inteligencia artificial. Ver [[Bastionado de redes y sistemas/Unidad 5 Configuración de dispositivos y sistemas/Apuntes/4. Seguridad del puesto de trabajo y endpoint\|UD5-4. Seguridad del puesto de trabajo y endpoint]].

Para elegir antivirus hay que basarse en **laboratorios independientes** (AV-Comparatives, AV-Test, Virus Bulletin, ICSA Labs), no en los informes de los fabricantes.

### 6.2.2 Detección de rootkits en GNU/Linux

Los *rootkits* sustituyen binarios del sistema para ocultarse, por lo que el antivirus puede no detectarlos. Herramientas específicas:

```bash
# chkrootkit: análisis rápido
sudo apt install chkrootkit
sudo chkrootkit          # análisis estándar
sudo chkrootkit -q       # solo detecciones y alertas

# Rootkit Hunter: más completo (ficheros, logs, puertos abiertos...)
sudo apt install rkhunter
sudo rkhunter --update           # actualizar base de firmas
sudo rkhunter --list tests       # tests disponibles
sudo rkhunter --check            # análisis completo
sudo rkhunter --disable <test> --check
```

> [!tip]
> Ambos generan **falsos positivos**; usar los dos permite contrastar resultados.

### 6.2.3 Auditoría de hardening con Lynis

**Lynis** (GPL, desde 2007) realiza un análisis de salud del sistema para apoyar el *hardening*: arranque y servicios, kernel, memoria y procesos, usuarios y autenticación, shells, sistema de ficheros, almacenamiento, puertos y paquetes, red, software (web, SSH, SNMP, BBDD, PHP, logging)… Al final da un **índice de fortificación** y **sugerencias de mejora**.

```bash
sudo lynis audit system
```

## 6.3 Sistemas de detección de intrusos (IDS)

Un **IDS** (*Intrusion Detection System*) detecta intrusos analizando múltiples fuentes de log en busca de anomalías. Se diferencia de un **IPS** en que el IPS puede **tomar medidas** para paliar el daño. Un IDS **no detiene ataques por sí solo**: necesita otras herramientas, como un *firewall* para el bloqueo.

| Tipo | Enfoque | Ejemplos |
| :-: | --- | :-: |
| **HIDS** (*Host IDS*) | Un único equipo: sus registros de auditoría, ficheros, recursos | OSSEC, Wazuh, Samhain |
| **NIDS** (*Network IDS*) | Tráfico de la red a la que se conectan los hosts | Snort, Suricata, Bro, Kismet |

Ver [[Bastionado de redes y sistemas/Unidad 5 Configuración de dispositivos y sistemas/Apuntes/13. Herramientas de monitorización IDS e IPS\|UD5-13. Herramientas de monitorización IDS e IPS]] (UD5).

### 6.3.1 Subcategorías de HIDS

- **Verificadores de integridad (SIV):** vigilan modificaciones no autorizadas de ficheros (típicamente *rootkits*). Ej.: Tripwire (Linux), SFC (Windows).
- **Monitores de registros:** buscan patrones de ataque en los logs. Ej.: swatch o *shellscripts* del administrador.
- **Sistemas de *deception* (*honeypots*):** simulan servicios vulnerables para registrar la actividad del atacante.

## 6.4 OSSEC

**OSSEC** es un HIDS de código abierto y gratuito (GPLv3), muy potente, configurable y multiplataforma. Realiza **análisis de registros, verificación de integridad, detección de rootkits, alertas y respuesta activa**. Tiene una versión de pago, **Atomic Enterprise OSSEC**.

> [!info] Actualización 2026
> OSSEC sigue disponible, pero su desarrollo es lento. En entornos actuales es muy habitual **Wazuh**, plataforma libre (XDR/SIEM) **basada en OSSEC**: mantiene el mismo modelo de agentes, `ossec.conf`, *syscheck* y *rootcheck*, y añade panel web, detección de vulnerabilidades y evaluación de configuración (SCA). Lo aprendido con OSSEC es directamente aplicable (actualizado, fuente: [Wazuh – README (GitHub)](https://github.com/wazuh/wazuh); [Wazuh documentation – Getting started](https://documentation.wazuh.com/current/getting-started/index.html)). Ver [[Bastionado de redes y sistemas/Unidad 5 Configuración de dispositivos y sistemas/Apuntes/14. SIEM\|UD5-14. SIEM]].

### 6.4.1 Funcionalidades

- **Antirootkit (*rootcheck*):** busca según patrones, firmas y ficheros definidos en la configuración.
- **Análisis de integridad (*syscheck*):** vigila **directorios** (y sus ficheros) mediante **hashes y permisos**. Primero calcula los hashes y después analiza periódicamente los cambios; con **inotify-tools** puede hacerlo **en tiempo real**. Se pueden ignorar ficheros concretos.
- **Análisis de logs:** los ***decoders*** extraen información (IP, usuario, terminal…) y las **reglas** la evalúan para generar alertas.
- **Alertas:** notificaciones con la regla que las generó y la información asociada.
- **Respuesta activa:** ejecuta acciones al saltar una alerta. Es **peligrosa por los falsos positivos**: solo debe usarse cuando se controlan totalmente las alertas del entorno.

### 6.4.2 Arquitectura

- **Servidor:** monitoriza y registra la actividad de los agentes (y actúa también como agente de sí mismo).
- **Agentes:** se instalan en cada máquina a supervisar (Windows, Linux, Mac) y envían la información al servidor de forma **cifrada** mediante una **PSK**.

### 6.4.3 Ficheros y directorios

Se instala en `/var/ossec/`:

| Ruta | Contenido |
| --- | --- |
| `/var/ossec/etc/ossec.conf` | Configuración principal (rootcheck, integridad, reglas…) |
| `/var/ossec/etc/shared/` | Reglas antirootkit y patrones de configuración base (**test CIS**) |
| `/var/ossec/etc/decoder.xml` | Cómo extraer información de los logs |
| `/var/ossec/rules/` | Reglas con descripción y **nivel de alerta** (p. ej. `pam_rules.xml`) |
| `/var/ossec/logs/alerts/alerts.log` | Registro principal de alertas |
| `/var/ossec/bin/` | Ejecutables (**no están en el PATH**) |
| `/var/ossec/queue/`, `stats/`, `tmp/`, `var/` | Colas, estadísticas, temporales y PID de los procesos |
| `/etc/init.d/ossec` | Script de inicio (llama a `ossec-control`) |
| `/etc/ossec-init.conf` | Directorio de trabajo y tipo de instalación (`TYPE`) |

### 6.4.4 Ejecutables principales

- **`ossec-control`:** inicia, para y reinicia los demonios.
- **`agent_control`:** consulta los agentes y relanza *syscheck*/*rootcheck* en ellos.
- **`manage_agents`:** gestiona las **claves de autenticación** de los agentes.
- **`syscheck_control`:** administra la base de datos de integridad.
- **`rootcheck_control`:** consulta las anomalías de *rootcheck* (resueltas y pendientes) y su última ejecución.

### 6.4.5 Instalación (servidor + agente)

OSSEC no está en los repositorios oficiales de Debian/Ubuntu; se usa el repositorio de Atomicorp. En **ambas máquinas**:

```bash
wget -q -O - https://updates.atomicorp.com/installers/atomic | sudo bash
sudo apt update
sudo apt install inotify-tools
```

**Servidor:**

```bash
sudo apt install ossec-hids-server
sudo service ossec start
sudo /var/ossec/bin/manage_agents   # A: añadir agente; E: extraer su clave (PSK)
```

**Cliente (agente):**

```bash
sudo apt install ossec-hids-agent
sudo touch /var/ossec/queue/rids/sender
sudo /var/ossec/bin/manage_agents   # I: importar la PSK generada en el servidor
# Editar /var/ossec/etc/ossec.conf e indicar la IP del servidor
sudo service ossec start
```

**Integridad en tiempo real** (en `/var/ossec/etc/ossec.conf` del agente):

```xml
<!-- antes -->
<directories check_all="yes">/etc,/usr/bin,/usr/sbin</directories>
<!-- después -->
<directories realtime="yes" check_all="yes">/etc,/usr/bin,/usr/sbin</directories>
```

```bash
sudo service ossec restart
```

> [!note]
> El tiempo real no funciona mientras *syscheck* calcula los hashes iniciales.

### 6.4.6 Pruebas de funcionamiento

- Comprobar desde el servidor que el agente está activo: `/var/ossec/bin/agent_control` (opción `-l` para listar agentes; actualizado, fuente: [OSSEC docs – agent_control](https://www.ossec.net/docs/docs/programs/agent_control.html)).
- Provocar eventos en el cliente y verlos centralizados en `/var/ossec/logs/alerts/alerts.log`:
  - Contraseña incorrecta con `sudo`.
  - Modificación de `/etc/passwd`.

```bash
sudo tail -f /var/ossec/logs/alerts/alerts.log
```

Incluso con la configuración por defecto, OSSEC resulta muy efectivo; puede complementarse con una **interfaz web**.
