# 7. Pluggable Authentication Modules (PAM)

> [!warning] No confundir
> En esta unidad **PAM** = *Pluggable Authentication Modules* (Linux). En la UD3, PAM = *Privileged Access Management* (ver [[Bastionado de redes y sistemas/Unidad 3 Administración de credenciales de acceso/Apuntes/6. Gestión de cuentas privilegiadas\|UD3-6. Gestión de cuentas privilegiadas]]).

## 7.1 Qué es PAM

**PAM** es un mecanismo de autenticación **flexible** que **abstrae a las aplicaciones del proceso de identificación**. No es un modelo de autenticación en sí, sino una **capa intermedia** (interfaz) entre las aplicaciones y los distintos sistemas de autenticación.

- Una aplicación preparada para PAM puede usar **distintos métodos** (contraseña, *token*, biometría…) **sin modificar la aplicación**.
- Incluye otras opciones, como **restringir el acceso a horarios** preestablecidos.
- En Linux, la mayoría de aspectos de la autenticación de usuarios se gestionan con PAM.

**Ventajas:**

- **Esquema de autenticación común** para gran variedad de aplicaciones.
- **Flexibilidad y control** tanto para administradores como para desarrolladores.
- Los desarrolladores **no tienen que crear sus propios esquemas** de autenticación.

## 7.2 Tipos de módulos

| Tipo | Función |
| :-: | --- |
| `auth` | Servicio de **autenticación** (comprobar la identidad). |
| `account` | **Administración de cuentas** (caducidad, restricciones de acceso). |
| `session` | **Gestión de sesiones** (tareas al abrir/cerrar sesión). |
| `password` | **Gestión de contraseñas** (cambio y requisitos). |

## 7.3 Ficheros de configuración

Cada servicio que usa PAM tiene un fichero en **`/etc/pam.d/`** (p. ej. `login`, `sshd`, `common-auth`, `common-password`, `system-auth`). Cada línea sigue la estructura:

```text
tipo   control   módulo   [argumentos]
```

- **tipo:** `auth`, `account`, `session` o `password`. Las entradas del mismo tipo forman una **pila** y se ejecutan secuencialmente.
- **control:** qué hacer ante el éxito o fracaso del módulo:
  - **`required`:** debe tener éxito para que la pila tenga éxito (se siguen ejecutando los demás).
  - **`requisite`:** como *required* pero más estricto: si falla, devuelve error y **no se ejecutan** los demás.
  - **`sufficient`:** si tiene éxito, **no se ejecutan más** módulos del mismo tipo; si falla, se continúa.
  - **`optional`:** solo cuenta si ningún otro módulo del mismo tipo ha determinado éxito o fracaso.
- **módulo:** ubicación del fichero del módulo (`.so`).
- **argumentos:** propios de cada módulo (ver su documentación).

`/etc/login.defs` es usado por el módulo **`pam_unix`** para las políticas de contraseñas de los nuevos usuarios (ver [[Bastionado de redes y sistemas/Unidad 2 Control de acceso y autenticación/Apuntes/5. Control de acceso#5.8.4 Política de contraseñas y comprobaciones generales\|5.8.4]]).

## 7.4 Políticas de cuentas con PAM

### 7.4.1 Complejidad de las contraseñas: `pam_cracklib` y `pam_pwquality`

`pam_cracklib` comprueba la fortaleza: que no se parezca a palabras de diccionario, longitud mínima, que no sea una modificación de la anterior y que contenga ciertas clases de caracteres. `pam_passwdqc` permite requisitos aún más exigentes. Ejemplo en `/etc/pam.d/common-password`:

```text
password required pam_cracklib.so retry=3 minlen=14 dcredit=-1 ucredit=-1 ocredit=-1 lcredit=-1
```

Exige al menos una mayúscula, una minúscula, un dígito y un símbolo, y 14 caracteres como mínimo.

| Opción | Significado |
| :-: | --- |
| `retry` | Intentos antes de devolver error |
| `minlen` | Longitud mínima |
| `difok` | Caracteres que deben cambiar respecto a la contraseña anterior |
| `ucredit` / `lcredit` | Mayúsculas / minúsculas |
| `dcredit` | Dígitos |
| `ocredit` | Otros símbolos |

> [!important] Créditos negativos y positivos
> - `ucredit=-3`: **como mínimo** 3 mayúsculas.
> - `ucredit=+3`: **como máximo** 3 mayúsculas cuentan como "crédito" para alcanzar `minlen`.

Actualmente se usa **`pam_pwquality`** (mejora de *cracklib*), configurado en **`/etc/security/pwquality.conf`**. Además de `minlen`, `dcredit`, `ucredit`, `lcredit`, `ocredit` y `difok`:

| Opción | Significado |
| :-: | --- |
| `badwords` | Palabras (separadas por espacios) prohibidas |
| `minclass` | Nº mínimo de clases de caracteres |
| `maxrepeat` | Máximo de caracteres repetidos |
| `maxclassrepeat` | Máximo de caracteres consecutivos de la misma clase |
| `dictpath` | Ruta a los diccionarios de *cracklib* |

```bash
pwscore        # evalúa la robustez de una contraseña (0-100)
```

### 7.4.2 Bloqueo por intentos fallidos: `pam_tally2`

Bloquear a quien falla repetidamente la contraseña previene **fuerza bruta** y accesos no autorizados. En `/etc/pam.d/common-auth`:

```text
auth    required  pam_tally2.so  deny=4 unlock_time=900 even_deny_root
# variante del Bloque 2:
auth    required  pam_tally2.so  deny=5 onerr=fail unlock_time=900
account required  pam_tally2.so
```

- **`deny`:** intentos permitidos antes de bloquear.
- **`unlock_time`:** segundos hasta el desbloqueo automático.
- **`even_deny_root`:** bloquea también a root.
- **`onerr=fail`:** si el módulo falla, deniega.

```bash
pam_tally2                  # intentos fallidos por usuario
pam_tally2 -u juan          # de un usuario
pam_tally2 -u juan --reset  # pone a cero el contador (desbloquea)
```

> [!info] Actualización 2026
> `pam_tally2` fue eliminado de Linux-PAM (desde la versión 1.5.0) y se sustituye por **`pam_faillock`**, que se configura en `/etc/security/faillock.conf` (`deny`, `unlock_time`, `even_deny_root`…); el contador se consulta con `faillock --user juan` y se pone a cero con `faillock --user juan --reset` (actualizado, fuente: [pam_faillock(8) – Linux manual page](https://man7.org/linux/man-pages/man8/pam_faillock.8.html)).

### 7.4.3 Algoritmo de *hash* SHA-512

```text
# /etc/pam.d/system-auth
password sufficient pam_unix.so sha512 shadow nullok try_first_pass use_authtok
# /etc/login.defs
MD5_CRYPT_ENAB no
ENCRYPT_METHOD SHA512
# /etc/libuser.conf
crypt_style = sha512
```

### 7.4.4 Limitar la reutilización de contraseñas

Para impedir reutilizar las **5 últimas** contraseñas, en `/etc/pam.d/system-auth` se añade `remember` a las opciones existentes de `pam_unix`:

```text
password sufficient pam_unix.so <opciones_existentes> remember=5
```

> [!tip] Relación con los criterios
> PAM es la herramienta con la que se **implantan** en Linux las políticas de contraseñas del criterio b ([[Bastionado de redes y sistemas/Unidad 2 Control de acceso y autenticación/Apuntes/3. Mecanismos y factores de autenticación#3.3.5 Políticas de contraseñas\|3.3.5]]) y permite integrar otros métodos (*tokens*, OTP, biometría) de los criterios c, d y e.
