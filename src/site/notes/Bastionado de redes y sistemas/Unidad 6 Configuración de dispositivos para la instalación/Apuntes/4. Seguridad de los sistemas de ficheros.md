# 4. Seguridad de los sistemas de ficheros

La seguridad del sistema de ficheros es fundamental para proteger los datos de **accesos no autorizados** y de posibles **daños**. La primera barrera son los **permisos** sobre ficheros y directorios.

## 4.1 Permisos

Cada fichero tiene un **usuario** propietario y un **grupo**, y tres conjuntos de bits de permisos: **propietario**, **grupo** y **resto de usuarios**. Cada conjunto tiene lectura (`r`), escritura (`w`) y ejecución (`x`); su significado cambia si se trata de un fichero o de un directorio.

La primera norma es **asignar los permisos adecuados** a cada fichero y usuario. Para controlar los permisos con los que se crean los ficheros se usa `umask` (incluido en `.profile` o `.cshrc`):

| `umask` | Permisos de ficheros nuevos |
| :-: | :-: |
| 022 | `rw-r--r--` |
| 077 | `rw-------` |

> [!tip] Comprobación de permisos peligrosos
> Un directorio con escritura para todos puede ser un fallo de seguridad:
> ```bash
> find / -type d -perm -002
> ```

## 4.2 Permisos especiales

Cada conjunto tiene un cuarto bit:

- **setuid:** al ejecutar el programa se adquieren los derechos del **propietario** (cambia el usuario efectivo). Ej.: `sendmail` con setuid de *root* para escribir en ficheros de correo.
- **setgid:** análogo para el **grupo**. En directorios, lo que se crea dentro pertenece al grupo del directorio.
- ***sticky bit*:** trato especial de la imagen de un ejecutable; hoy es sobre todo por compatibilidad con UNIX antiguos.

> [!warning]
> Los ficheros con setuid pueden ser **brechas de entrada**: si un atacante consigue el EUID 0 puede editar el fichero de contraseñas y crearse una cuenta de *root*. Conviene localizarlos:
> ```bash
> find / -perm /6000
> ```

Más sobre permisos y control de acceso en [[Bastionado de redes y sistemas/Unidad 2 Control de acceso y autenticación/Apuntes/5. Control de acceso\|UD2-5. Control de acceso]].

## 4.3 Cifrado del sistema de ficheros

El **cifrado** vuelve ilegibles los datos; solo quien tenga la clave correcta puede descifrarlos. Cifrar discos, SSD, particiones, carpetas y archivos es sencillo y aporta seguridad sobre todo en equipos expuestos a **acceso físico no autorizado** (portátiles, servidores en lugares poco vigilados) y en **dispositivos externos** (discos extraíbles, *pendrives*).

### 4.3.1 Cifrado en GNU-Linux. LUKS

Opciones: **dm-crypt**, **LUKS**, **eCryptfs** o **VeraCrypt**. Nos centramos en **LUKS** (*Linux Unified Key Setup*):

- Cifra **discos, particiones y volúmenes lógicos**.
- Sencillo de usar, **incluido en el kernel** (alto rendimiento) y con gestión flexible de claves.
- Es el **estándar** en Linux: disponible sin instalar software adicional.
- Se puede activar **durante la instalación** del sistema para la partición del sistema o de otras, p. ej. `/home`.
- Sin la contraseña maestra, el acceso (desde un Live-CD/USB o por sustracción del equipo) resulta imposible (aunque la seguridad al 100 % no existe).

> [!info] Contenido complementario (fuente externa)
> Las versiones actuales de `cryptsetup` crean por defecto volúmenes **LUKS2** (cabecera redundante, derivación de clave **Argon2id**). Comandos básicos (¡`luksFormat` borra la partición!):
>
> ```bash
> sudo cryptsetup luksFormat /dev/sdb1            # inicializa LUKS2 y pide la frase de paso
> sudo cryptsetup open /dev/sdb1 datos            # equivale al antiguo luksOpen → /dev/mapper/datos
> sudo mkfs.ext4 /dev/mapper/datos && sudo mount /dev/mapper/datos /mnt
> sudo cryptsetup luksDump /dev/sdb1              # versión, keyslots, KDF
> sudo cryptsetup luksHeaderBackup /dev/sdb1 --header-backup-file cabecera.img
> sudo umount /mnt && sudo cryptsetup close datos
> # apertura al arranque: /etc/crypttab →  datos  UUID=<uuid>  none  luks
> ```
>
> Fuentes: [cryptsetup(8)](https://man7.org/linux/man-pages/man8/cryptsetup.8.html), [crypttab(5)](https://man7.org/linux/man-pages/man5/crypttab.5.html), [cryptsetup FAQ](https://gitlab.com/cryptsetup/cryptsetup/-/wikis/FrequentlyAskedQuestions).

### 4.3.2 Cifrado en Windows. EFS

**EFS** (*Encrypted File System*) es el cifrado nativo de Windows sobre **NTFS** (Windows 2000 Server, Vista y posteriores). Combina criptografía **simétrica** (AES o DES) y **asimétrica** (RSA) de forma transparente. No está disponible en **Windows 10 Home** (tampoco en Windows 11 Home; sí en Pro, Enterprise y Education).

**Activación:** clic derecho en el archivo/carpeta → **Propiedades** → **Opciones avanzadas** → **Cifrar contenido para proteger datos** → Aceptar → Aplicar. Se puede elegir cifrar solo el archivo o también su carpeta; los archivos cifrados muestran un **candado**. También con `cipher.exe`.

- Lo que se guarda en una carpeta marcada se cifra (no lo que ya estaba). Otro usuario no podrá leerlo, ni arrancando desde un medio *live*.
- El certificado usa el **SID** del usuario: si se borra el usuario, los datos son **irrecuperables**. Hay que **copiar el certificado y las claves** (el sistema lo propone al activar EFS):

```bat
cipher /X nombre_fichero
```

Genera un fichero **.PFX** protegido con contraseña; se restaura con clic derecho → **Instalar PFX**.

- **Agentes de recuperación** (Directorio Activo): rol de dominio (administradores de dominio o locales) que permite recuperar archivos cifrados de usuarios que se van o se borran. Windows cifra con **dos credenciales**: la del usuario y la del agente. Se definen por directiva y se consultan en el botón **Detalles** de la carpeta cifrada.

> [!warning] Inconvenientes de EFS
> - La seguridad depende de la **identidad del usuario**: con su contraseña (o una cuenta de **Administrador**) se accede a los datos.
> - **No cifra el disco completo**: arrancando desde un medio externo o conectando el disco a otro equipo se leen los datos no cifrados e incluso contraseñas en caché del registro. Para eso existe **BitLocker** (ver [[Bastionado de redes y sistemas/Unidad 6 Configuración de dispositivos para la instalación/Apuntes/5. Hardening de sistemas#5.5 Cifrado de SSD, discos duros o particiones\|cifrado de discos]]).

## 4.4 Particionado

Una **partición** es cada división de una unidad física de almacenamiento: es como tener varios discos en uno, cada uno con su propio **sistema de archivos**. Usos:

- Una partición dedicada a **datos sensibles** con medidas de seguridad propias, sin interferir con el resto del sistema.
- **Copias de seguridad**.
- Instalar **varios sistemas operativos**.
- En GNU/Linux, separar en particiones los distintos tipos de archivos del sistema.

### 4.4.1 Tipos de particiones (MBR)

- **Primaria:** depende de la tabla de particiones; es la que detecta el equipo al arrancar, donde se instalan los sistemas operativos. **Máximo cuatro**. Un disco formateado entero es una primaria que ocupa todo el espacio.
- **Extendida o secundaria:** permite superar el límite de cuatro; **no admite sistema operativo**, solo sirve de contenedor. Solo puede haber **una** (el disco queda con tres primarias + la extendida).
- **Lógica:** particiones dentro de la extendida; solo requieren tamaño y sistema de archivos (FAT32, NTFS, ext2…) y funcionan como dispositivos independientes.

Con **GPT/UEFI** el límite pasa a 128 particiones (ver [[Bastionado de redes y sistemas/Unidad 6 Configuración de dispositivos para la instalación/Apuntes/3. Seguridad en el arranque#3.1.1 BIOS frente a UEFI\|BIOS frente a UEFI]]).

> [!info] Contenido complementario (fuente externa)
> Guías de bastionado como los **CIS Benchmarks** recomiendan particiones separadas para `/tmp`, `/var`, `/var/tmp`, `/var/log`, `/var/log/audit` y `/home`, de modo que llenar una no bloquee el sistema y se puedan aplicar opciones de montaje restrictivas:
> - `nodev`: no interpreta ficheros de dispositivo.
> - `nosuid`: ignora los bits SUID/SGID.
> - `noexec`: impide ejecutar binarios directamente desde ese sistema de ficheros (no bloquea intérpretes, p. ej. `sh script`).
>
> ```text
> # /etc/fstab (ejemplo)
> UUID=<uuid-home>  /home      ext4   defaults,nodev,nosuid         0 2
> tmpfs             /tmp       tmpfs  defaults,nodev,nosuid,noexec  0 0
> UUID=<uuid-vtmp>  /var/tmp   ext4   defaults,nodev,nosuid,noexec  0 2
> ```
>
> Comprobar con `findmnt /tmp` o `mount | grep /tmp`.
> Fuentes: [mount(8) – opciones de montaje](https://man7.org/linux/man-pages/man8/mount.8.html), [CIS Benchmarks – Ubuntu Linux](https://www.cisecurity.org/benchmark/ubuntu_linux).

### 4.4.2 Particionar un disco en Windows 10

1. Menú Inicio → escribir *partición* → **Crear y formatear particiones del disco duro** (Administración de discos).
2. Clic derecho sobre el volumen → **Reducir volumen** (o *Eliminar volumen* / *Formatear*) para liberar espacio; indicar el tamaño en MB.
3. Aparece espacio **No asignado**: clic derecho → **Nuevo volumen simple**.
4. Elegir el **tamaño** de la partición.
5. Asignar una **letra de unidad** (o *No asignar una letra o ruta de acceso*).
6. **Formatear** (recomendado): sistema de archivos, tamaño de unidad y etiqueta.
7. Revisar el resumen y finalizar.
