# Unidad 3: Sistemas operativos. Gestión de archivos y almacenamiento

> [!abstract] Criterios que se trabajan
> **CE3D** (unidades lógicas: RAID y volúmenes) y **CE3G** (instalar y evaluar utilidades: `e4defrag`, `fsck`, `e2fsck`, `mdadm`). Contenido **BC3_6** (desfragmentación, chequeo, volúmenes y cifrado).

## 5.1 Desfragmentación

La **fragmentación** es la dispersión de los datos de un mismo archivo por el medio de almacenamiento. El sistema de archivos sabe dónde está cada bloque, pero en los **discos mecánicos** el cabezal debe moverse continuamente, lo que empeora los tiempos de lectura y escritura.

La **desfragmentación** une los bloques de un mismo archivo. Con mucha fragmentación aparecen numerosos huecos.

![u3_fragmentacion_disco.jpg](/img/user/Sistemas%20Inform%C3%A1ticos/03_Recursos/Imagenes/Unidad%203/u3_fragmentacion_disco.jpg)

| Linux | Windows |
| --- | --- |
| En general **no necesita desfragmentarse**: usa asignación inteligente por ***extents***. Si hace falta: `e4defrag [opciones] objetivo`. | Explorador de archivos → **Propiedades** de la unidad → pestaña **Herramientas** → Desfragmentar; o pestaña **Herramientas de unidad** de la cinta. |

Opciones de `e4defrag`:

- `-c`: recuento de la fragmentación actual frente a la ideal.
- `-v`: muestra mensajes de error antes y después de desfragmentar.

```bash
sudo e4defrag -c /dev/sdb1
```

## 5.2 Chequeo

Los **datos** son el componente más importante. Problemas habituales de los discos:

1. Malware.
2. Fallos en componentes electrónicos.
3. Fluctuaciones de tensión.
4. Daños físicos (caídas, desgaste); los mecánicos son más propensos por sus partes móviles.
5. Errores de *firmware* o de actualización de drivers.

**S.M.A.R.T.** (*Self Monitoring Analysis and Reporting Technology*): la mayoría de discos detecta e informa de errores. Con software compatible (la BIOS u otra aplicación) da el estado del disco e incluso avisa de un **fallo inminente**.

> [!tip] Monitorización
> Según la importancia de los datos, hay que monitorizar continuamente o chequear periódicamente; es muy recomendable instalar una aplicación de monitorización del estado de los discos.

### 5.2.1 `fsck` y `e2fsck` (Linux)

`fsck` es, como `mkfs`, un ***front-end*** de otros programas, como `e2fsck` (familia ext). Para ver los ejecutables: `ls -l /sbin/*fsck*`.

`fsck [opciones] [sistema_de_archivos]`

| Opción | Efecto |
| :-: | --- |
| `-A` | Chequea todo lo indicado en `/etc/fstab` (sin argumento; se lanza en el arranque). |
| `-V` | Detalla las acciones. |
| `-t tipo` | Tipo: `ext2`, `ext3`, `ext4`, `fat`, `ntfs`… |
| `-a` | Repara sin pedir confirmación. |
| `-r` | Pide confirmación antes de reparar (opción del comprobador específico; en el `fsck` actual de util-linux, `-r` muestra estadísticas de cada comprobación). |

`e2fsck [opciones] sistema_de_archivos`

| Opción | Efecto |
| :-: | --- |
| `-p` | Repara automáticamente (incompatible con `-n` y `-y`). |
| `-c` | Usa `badblocks` para buscar bloques defectuosos y evitar su uso. |
| `-y` | Responde "sí" a todo. |
| `-n` | Responde "no" a todo. |
| `-v` | Detalla las acciones. |
| `-D` | Optimiza los directorios. |

```bash
sudo fsck -t ext4 /dev/sdb1
sudo e2fsck -c /dev/sdb1
shutdown -r now      # reiniciar tras reparar
```

> [!note] Buenas prácticas
> - **Desmontar** antes de chequear, para asegurar la integridad.
> - **Reiniciar** tras cambios hechos por estas herramientas.
> - En `/etc/fstab`, la columna **pass** automatiza el chequeo en el arranque: poner **1** para la raíz `/` (una vez iniciado el sistema no se puede chequear con garantías).

## 5.3 RAID

**RAID** (*Redundant Array of Independent Disks*): nivel o configuración de un grupo de discos para aumentar la **integridad**, la **capacidad**, la **velocidad** o disminuir el **riesgo de fallos**. Se implementa por **software** (del SO o no) o por **hardware** (tarjeta controladora o chipset de la placa), distribuyendo o redundando datos entre discos.

| Nivel | Funcionamiento | Discos | Ventajas | Inconvenientes |
| :-: | --- | :-: | --- | --- |
| **RAID 0** | Divide los datos entre discos **sin redundancia**. | ≥ 2 | Más velocidad de lectura y escritura (con controladores distintos). | No es RAID "propio": sin tolerancia a fallos. |
| **RAID 1** | **Copia exacta** (espejo). | ≥ 2 | Fiabilidad; más velocidad de lectura. | Se desaprovecha espacio. |
| **RAID 5** | Distribuye los bloques y una **paridad** repartida en todos los discos. | ≥ 3 | Reconstruye un disco caído; menos espacio redundante que RAID 1; mejor lectura. | Escrituras más costosas (cálculo de paridad). |
| **RAID 0+1 / 1+0 / 5+0** | Niveles **anidados** que combinan ventajas. | — | — | — |
| **JBOD / RAID lineal** | Une varios discos en uno lógico. | ≥ 2 | Tamaño = suma de todos. | Sin redundancia ni mejora de rendimiento. |

> [!note] Paridad en RAID 5
> La paridad de RAID 5 no es un CRC: es la operación **XOR** de los bloques de datos de cada franja ($P = D_1 \oplus D_2 \oplus \dots$). Si falla un disco, su bloque se reconstruye haciendo XOR de los restantes. RAID 6 añade una segunda paridad (código de Reed-Solomon) y tolera dos discos caídos.

> [!info] Fuentes
> - [Wikipedia: Standard RAID levels](https://en.wikipedia.org/wiki/Standard_RAID_levels)

## 5.4 Administración de RAID en Linux: `mdadm`

**mdadm** (*Multiple Device Administrator*). Instalación (la fuente usa Ubuntu): `sudo apt install mdadm` (en openSUSE: `sudo zypper install mdadm`).

- `cat /proc/mdstat`: comprueba si hay multidispositivos; la línea **Personalities** muestra los niveles disponibles.
- Se puede crear sobre discos o particiones, aunque no tengan el mismo tamaño: si difieren más de un **1 %**, avisa y toma el **más pequeño**.

| Acción | Comando |
| --- | --- |
| Crear | `mdadm --create /dev/mdX --level=Y --raid-devices=Z disp1 disp2…` |
| Marcar un disco como defectuoso | `mdadm /dev/mdX --fail /dev/sdY` |
| Quitar un disco | `mdadm /dev/mdX --remove /dev/sdY` |
| Añadir un disco | `mdadm /dev/mdX --add /dev/sdY` |
| Estado de todos | `cat /proc/mdstat` |
| Información de todos | `mdadm --detail --scan` |
| Información de uno | `mdadm --detail /dev/mdX` (y `--scan`) |
| Examinar un miembro | `mdadm --examine /dev/sdX` |
| Detener | `mdadm --stop /dev/mdX` |
| Borrar el superbloque | `mdadm --zero-superblock /dev/sdY` |

Valores de `--level`: `linear`; `raid0`, `0`, `stripe`; `mirror`, `raid1`, `1`; `raid4`, `4`; `raid5`, `5`; `raid6`, `6`; `raid10`, `10`.

### 5.4.1 Crear un RAID

1. Particionar con `fdisk` cada disco (tabla **MBR**):
   1. `sudo fdisk /dev/sd?` → `n` (partición que ocupe todo el disco).
   2. `t` → tipo **`fd`** (*Linux raid auto*).
   3. `w` para grabar.
2. Crear el RAID con `mdadm --create` y comprobar que ha terminado con `sudo mdadm --detail /dev/md?`.
3. Formatear: `sudo mkfs.ext4 /dev/md?`.
4. Registrar el RAID en `/etc/mdadm/mdadm.conf` y actualizar el initramfs.
5. Crear un punto de montaje (p. ej. en `/mnt`) y añadirlo a `/etc/fstab`.

```bash
sudo mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb1 /dev/sdc1
sudo mdadm --detail /dev/md0
sudo mkfs.ext4 /dev/md0
sudo /usr/share/mdadm/mkconf | sudo tee /etc/mdadm/mdadm.conf
# o, como root: mdadm --detail /dev/md0 --scan >> /etc/mdadm/mdadm.conf
sudo update-initramfs -u
```

> [!note] En openSUSE
> `mkconf`, `/etc/mdadm/mdadm.conf` y `update-initramfs` son de Debian/Ubuntu. En openSUSE el fichero es **`/etc/mdadm.conf`** y el initramfs se regenera con **`dracut`**:
> ```bash
> sudo mdadm --detail --scan | sudo tee -a /etc/mdadm.conf
> sudo dracut -f
> ```

> [!info] Fuentes
> - [SUSE: Software RAID configuration](https://documentation.suse.com/sles/15-SP6/html/SLES-all/cha-raid.html)
> - [SLES 15 SP4 Release Notes (`mkinitrd` sustituido por `dracut`)](https://www.suse.com/releasenotes/x86_64/SUSE-SLES/15-SP4/index.html)

### 5.4.2 Eliminar un RAID

1. Desmontar: `sudo umount dispositivo`.
2. Detener: `sudo mdadm --stop /dev/md?`.
3. Borrar el superbloque de cada miembro: `sudo mdadm --zero-superblock /dev/sde1` (ídem `sdd1`, `sdg1`…).
4. Si arrancaba con el sistema, quitar su línea de `/etc/fstab` y actualizar el initramfs.

Referencia de la fuente: <https://recoverhdd.es/blog/creating-the-software-mdadm-raid-in-linux.html>

## 5.5 Discos dinámicos y volúmenes en Windows

Desde el **Administrador de discos** (ver [[Sistemas Informáticos/Unidad 3 Sistemas operativos. Gestión de archivos y almacenamiento/Apuntes/4. Montaje, particionado y formateo#4.5 Administrador de discos de Windows\|Administrador de discos]]) los discos se convierten en **dinámicos** (deben estar inicializados), lo que permite crear volúmenes:

| Volumen | Equivale a | Descripción |
| --- | :-: | --- |
| **Simple** | — | Una única unidad en un disco. |
| **Distribuido** | JBOD | Une espacios de distintos discos en una unidad lógica. |
| **Seccionado** | RAID 0 | Gran rendimiento; si falla un disco, falla el volumen. |
| **Reflejado** | RAID 1 | Redundancia de datos. |
| **RAID-5** | RAID 5 | Tres o más discos con tolerancia a fallos. Solo en **Windows Server**. |

> [!note] Situación actual
> Microsoft considera los discos dinámicos **obsoletos** (salvo para reflejar el volumen de arranque) y recomienda **Espacios de almacenamiento** (*Storage Spaces*) para agrupar discos con redundancia. Fuente: [Microsoft Learn: Basic and dynamic disks](https://learn.microsoft.com/en-us/windows/win32/fileio/basic-and-dynamic-disks).

> [!warning] Conversión
> De **básico a dinámico** no se pierden datos; de **dinámico a básico**, sí.
