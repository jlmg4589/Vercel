# Unidad 3: Sistemas operativos. Gestión de archivos y almacenamiento

> [!abstract] Criterios que se trabajan
> **CE3A** (comparar sistemas de archivos). Contenido **BC3_1** y, en parte, **BC3_6** (cifrado como característica del sistema de archivos).

Los sistemas operativos gestionan la información de los medios de almacenamiento gracias a los **sistemas de archivos**, que definen cómo se almacena la información y ofrecen mecanismos para operar sobre ella.

## 1.1 Archivos, directorios y objetivos

- **Archivo (fichero):** herramienta fundamental de abstracción lógica de la información; es la **unidad lógica mínima de almacenamiento**. El usuario no necesita conocer su estructura interna.
- **Directorio (carpeta):** el sistema lo interpreta como un fichero que actúa como **contenedor lógico** de archivos o de otros directorios.

Objetivos de un sistema de archivos:

- Acceder a la información de los ficheros.
- Crear, eliminar y modificar ficheros.
- Realizar copias de seguridad.
- Utilizar herramientas de recuperación de información.
- Maximizar el rendimiento de las operaciones sobre archivos.
- Administrar el espacio: asignación del espacio libre y del ocupado.

## 1.2 Clúster y fragmentación

El **espacio de asignación** o **clúster** se fija durante el **formateo** y define el **tamaño mínimo** que ocupa un archivo en ese medio. Símil: el **sector** es al disco (hardware) lo que el **clúster** es al sistema de archivos (software).

Si se conoce el tamaño medio de los archivos, se puede ajustar el clúster; lo habitual es aceptar el valor estándar que propone el sistema.

![u3_fragmentacion_cluster.jpg](/img/user/Sistemas%20Inform%C3%A1ticos/03_Recursos/Imagenes/Unidad%203/u3_fragmentacion_cluster.jpg)

| Tipo | Significado |
| --- | --- |
| **Fragmentación interna** | Espacio desperdiciado dentro del último clúster de un archivo (el archivo no lo llena). |
| **Fragmentación externa** | El **espacio libre** queda dividido en muchos huecos pequeños no contiguos, aunque en total haya sitio suficiente. |
| **Fragmentación de datos** | Bloques de un **mismo archivo** dispersos por el medio (ver [[Sistemas Informáticos/Unidad 3 Sistemas operativos. Gestión de archivos y almacenamiento/Apuntes/5. Mantenimiento de discos, RAID y volúmenes#5.1 Desfragmentación\|Desfragmentación]]). |

## 1.3 FAT (*File Allocation Table*)

Creado para **MS-DOS**. Muy compatible con distintos sistemas operativos, por lo que se usa en dispositivos externos para **intercambiar información** entre sistemas.

Limitaciones:

- Archivos de, como máximo, **4 GiB − 1 byte** (el tamaño se guarda en 32 bits).
- **Bajo rendimiento.**
- **Inseguro:** no permite cifrado, atributos y permisos limitados y **sin *journaling***.

| | FAT12 | FAT16 | FAT32 |
| --- | :-: | :-: | :-: |
| Bits para direccionar bloques | 12 b | 16 b | 32 b (28 b para clústeres) |
| Año de lanzamiento | 1977 | 1988 | 1996 (Windows 95) |
| Tamaño máximo de archivo | 32 MiB | 2 GiB | 4 GiB |
| Tamaño máximo de volumen | 32 MiB | 2 GiB | 2 TiB |

> [!note] Límite de volumen de FAT32
> El volumen máximo depende del tamaño de sector y de clúster:
> - **2 TiB** con sectores de 512 bytes ($2^{32}$ sectores × 512 B), el caso habitual: es el valor de la tabla.
> - **8 TiB** si se calcula con $2^{28}$ clústeres de 32 KiB (la cifra "teórica" de la fuente); **16 TiB** con sectores de 4 KiB.
> - La herramienta de formateo de Windows solo crea volúmenes FAT32 de hasta **32 GB**, aunque lea volúmenes mayores.

## 1.4 NTFS (*NT File System*)

Surgió con **Windows NT** para mejorar FAT. Cambia el mecanismo de almacenamiento: la información de los archivos se guarda como **metadatos**, los nombres en **Unicode** y la estructura en un formato orientado a **reducir la fragmentación** (punto débil de FAT).

- Archivos y volúmenes de hasta **256 TiB** con clústeres de 64 KiB (16 TiB con los clústeres por defecto de 4 KiB) y de hasta **8 PiB** con clústeres de 2 MiB desde Windows 10 1709 y Windows Server 2019. El límite teórico del formato es de 16 EiB.
- **Registro transaccional:** registra las operaciones sobre archivos para recuperar el contenido en caso de fallo.
- Nombres largos de hasta **255 caracteres** (LFN).
- Mejor soporte de metadatos.
- Estructuras de datos avanzadas (**árboles indexados**) para rendimiento y estabilidad.
- Seguridad: **listas de control de acceso**, **cifrado y compresión** de archivos y **cuotas de disco**.

## 1.5 exFAT

Publicado en **2006**, evolución de FAT. Diseñado para **medios extraíbles** (memorias USB, tarjetas, discos externos y SSD). Eficiente con soportes pequeños, pero admite archivos grandes y supera el límite de 4 GiB de FAT32. Compatible de forma nativa desde **Windows Vista SP1** (en XP, con una actualización), **macOS** 10.6.5 y **Linux** (kernel 5.4).

No tiene el *journaling* de NTFS, que provoca escrituras constantes y **desgastaría la memoria flash**, acortando su vida útil.

## 1.6 APFS

Sistema de archivos de **Apple**, mejora de su predecesor **HFS+**. Características similares a NTFS y ext4:

- Archivos y volúmenes de hasta **8 EiB**.
- Permite **cifrado** y está optimizado para almacenamiento **flash**.
- **Contenedores dinámicos:** en un mismo disco varias particiones comparten el espacio y su tamaño varía dinámicamente según lo que ocupen las demás.
- ***Copy-on-Write*** (la fuente propone investigarlo).

## 1.7 ext2, ext3 y ext4 (*Extended File System*)

Soportados por la mayoría de distribuciones Linux. ext3 mejora ext2 y ext4 es la sucesora de ext3. Características de **ext4**:

- Mantiene el ***journaling***.
- Ficheros de mayor tamaño gracias a los ***extents***.
- Archivos de hasta **16 TiB** (con bloques de 4 KiB) y volúmenes de hasta **1 EiB**.
- **No usa extensiones** como parte del nombre (en NTFS: `<nombre>.<extensión>`).
- Su estructura fundamental es el **i-nodo** (nodo índice), que guarda la metainformación del archivo: tipo, propietario, tamaño, fechas, etc.

> [!note] Conceptos clave
> - ***Journaling*:** registro o diario del sistema de archivos. Se anotan las acciones antes de realizar la operación; los sistemas que lo usan se llaman **transaccionales**.
> - ***Extent*:** conjunto de **bloques contiguos**, que da una velocidad de lectura y escritura mucho mayor.

```bash
stat archivo     # muestra la información del i-nodo de un archivo
```

## 1.8 Comparativa

| Característica | FAT32 | exFAT | NTFS | APFS | ext4 |
| --- | :-: | :-: | :-: | :-: | :-: |
| Sistema de origen | MS-DOS / Windows | Windows | Windows NT | macOS | Linux |
| Archivo máximo | 4 GiB | > 4 GiB | 256 TiB (8 PiB en Windows actual) | 8 EiB | 16 TiB |
| Volumen máximo | 2 TiB | — | 256 TiB (8 PiB en Windows actual) | 8 EiB | 1 EiB |
| *Journaling* | No | No | Sí (registro transaccional) | — | Sí |
| Cifrado | No | — | Sí | Sí | — |
| Uso típico | Intercambio entre SO | Extraíbles y flash | Discos de Windows | Discos de Apple | Discos de Linux |

"—": dato no indicado en la fuente.
