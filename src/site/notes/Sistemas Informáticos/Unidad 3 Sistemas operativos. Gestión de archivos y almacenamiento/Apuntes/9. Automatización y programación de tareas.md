# Unidad 3: Sistemas operativos. Gestión de archivos y almacenamiento

> [!abstract] Criterios que se trabajan
> **CE3F** (planificar y automatizar tareas). Contenido **BC3_7** (tareas automáticas, planificación). Fuente: Tema 4, apartados 7 (Automatización de tareas en Linux) y 8 (Programación de tareas en Windows).

Hay dos formas de planificar tareas:

| Tipo | Herramienta Linux | Repetición |
| --- | --- | :-: |
| **Momento puntual** | `at`, `batch` | No |
| **Recurrente** | `cron` | Sí |

## 9.1 Automatización de tareas en Linux

### 9.1.1 `at`

Lanza una tarea o conjunto de tareas **una sola vez** en una fecha y hora concretas. Instalación (la fuente usa Ubuntu): `sudo apt install at`.

Sintaxis: `at hora [fecha] [-f fichero]`

- Devuelve un *prompt* para escribir las órdenes; se guardan con **Ctrl + D**.
- Con `-f` las órdenes se leen de un fichero.

| Orden | Efecto |
| --- | --- |
| `at -l` | Lista las tareas pendientes. |
| `at -d num_tarea` | Elimina una tarea planificada. |
| `at -c num_tarea` | Muestra el desglose de una tarea. |

```bash
at 18:30 tomorrow        # también: at now + 2 hours, at 10:00 2026-12-24
at> tar -czf /tmp/copia.tgz ~/Documentos
at> <Ctrl+D>
at 08:00 -f tareas.txt
```

### 9.1.2 `batch`

Alternativa a `at` para **trabajos por lotes**: el **sistema** (el demonio `atd`, no el núcleo) decide cuándo ejecutarlos. Se lanzan de inmediato, pero si la **carga del sistema** es excesiva (por defecto **≥ 1,5**, configurable con `atd -l`) se retrasan. La carga media aparece en la primera línea de `top` (*load average*).

Adecuado para procesos que ocupan la CPU mucho tiempo con poca E/S.

```bash
batch < tareas      # "tareas" es un archivo de texto con órdenes
```

### 9.1.3 `cron`

**Demonio** que lanza órdenes o scripts de forma **periódica** según un archivo **crontab** (*cron table*).

- `/etc/crontab`: tareas de todo el sistema; solo lo edita el **superusuario**, el resto solo lo lee.
- Cada usuario puede tener **su propio crontab**.

Gestión del servicio (órdenes de la fuente, Ubuntu):

```bash
dpkg -l cron              # ¿está instalado?
systemctl status cron     # ¿está activo?
systemctl start cron      # iniciarlo
systemctl restart cron    # reiniciarlo
```

> [!note] En openSUSE
> El paquete se llama **`cronie`** y el servicio **`cron`**:
> ```bash
> rpm -q cronie             # ¿está instalado? (o: zypper se cronie)
> sudo zypper install cronie
> systemctl status cron
> ```
> El paquete de `at` es `at` y su demonio, `atd` (`sudo systemctl enable --now atd`).

#### Formato de una línea crontab

| Minuto | Hora | Día del mes | Mes | Día de la semana | Orden |
| :-: | :-: | :-: | :-: | :-: | --- |
| 0-59 | 0-23 | 1-31 | 1-12 | 0-7 (0 y 7 = domingo) | comando o script |

- `*`: cualquier valor válido (campo ignorado).
- `,`: lista sin espacios (`1,15`).
- `-`: rango mínimo-máximo (`1-5`).
- `/`: incremento sobre un rango o sobre `*` (`*/15` = cada 15 minutos; `0-23/2` = cada dos horas). La forma `0/15` no es válida en cron de Linux.

| Orden | Efecto |
| --- | --- |
| `crontab -e` | Edita el crontab del usuario (abre un editor). |
| `crontab -l` | Muestra el crontab del usuario. |
| `crontab -r` | Elimina el crontab. |
| `crontab -ri` | Pregunta antes de eliminarlo. |

También se puede escribir un archivo propio y cargarlo redirigiéndolo al comando `crontab`. Con `crontab -e` o `crontab archivo` no hace falta reiniciar nada: cron revisa los crontab cada minuto. Solo si se edita a mano un fichero del sistema y no se detecta el cambio se reinicia el servicio (`systemctl restart cron`).

```bash
# Ejemplos ilustrativos (las capturas de la fuente no son legibles)
30 2 * * 1-5  /home/luis/scripts/copia.sh      # 2:30, de lunes a viernes
0 */6 * * *   tar -czf /mnt/backup/docs.tgz /home/luis/Documentos   # cada 6 horas
crontab mis_tareas                               # cargar un archivo propio
```

> [!info] Fuentes
> - [crontab(5) (cronie)](https://man7.org/linux/man-pages/man5/crontab.5.html), [at(1) y atd(8)](https://manpages.debian.org/at)
> - [openSUSE Build Service: cronie](https://build.opensuse.org/package/show/Base:System/cronie)

> [!tip] Copias automáticas
> Combinar `cron` con `tar` permite automatizar las copias de [[Sistemas Informáticos/Unidad 3 Sistemas operativos. Gestión de archivos y almacenamiento/Apuntes/8. Clonación y copias de seguridad#8.4 Copias por comandos en Linux: `tar`\|8.4 Copias con tar]].

## 9.2 Programación de tareas en Windows

La utilidad **Programador de tareas** (en **Herramientas administrativas** de Windows 10 o **Herramientas de Windows** de Windows 11) ejecuta un comando asociado a un evento: a una hora, al iniciar sesión, al iniciar el equipo o ante un suceso concreto.

Crear una tarea: **Acción → Crear tarea**, o mejor **Crear tarea básica** (asistente):

1. **Nombre** y **descripción** de la tarea.
2. **Desencadenar:** instante, frecuencia o evento asociado.
3. **Acción:** comando o script que se ejecutará.
4. Marcando **Abrir el diálogo Propiedades para esta tarea al hacer clic en Finalizar** se revisan y modifican todas sus propiedades.

Las tareas del sistema o de un usuario se ven en la misma herramienta. Para probar una tarea sin esperar al desencadenante: seleccionarla y **Acción → Ejecutar**.
