# Unidad 3: Sistemas operativos. Gestión de archivos y almacenamiento

> [!abstract] Criterios que se trabajan
> **CE3B** (estructura y función de los directorios del sistema operativo). Contenido **BC3_2** (sistemas libres y propietarios).

## 2.1 Árbol y bosque

| Linux | Windows |
| --- | --- |
| Un único directorio principal, la **raíz** `/`, del que cuelga todo. La estructura se llama **árbol**. | Cada partición o disco es un árbol independiente con su propia raíz (`C:\`, `D:\`, `E:\`). El conjunto se llama **bosque**. |
| Separador `/` | Separador `\` |
| Ejemplo: `/home/usuario2/` | Ejemplo: `C:\Users` (`C:\Documents and Settings` en Windows XP) |

### 2.1.1 Conceptos de rutas

- **Ruta, camino o *path*:** localización de un directorio o archivo.
- **Directorio de trabajo actual:** donde estamos situados; se simboliza con `.`. Se muestra con `pwd` (*Print Working Directory*) en Linux y con `cd` sin argumentos en Windows.
- **Directorio padre:** el que está por encima en la jerarquía; se simboliza con `..`.
- **Directorio hijo:** el que está por debajo.
- **Ruta absoluta:** desde la raíz. Ejemplo: `cd /home/user`.
- **Ruta relativa:** desde el directorio actual, usando `.` y `..`. Ejemplo: `cd ./user`.

> [!tip] Trucos de la shell de Linux
> - **Tabulador:** autocompleta si solo hay una posibilidad; pulsado **dos veces** muestra todas las coincidencias.
> - Linux **distingue mayúsculas y minúsculas**.
> - **Ctrl + R** (*reverse-i-search*): busca en el historial de comandos, de la más reciente a la más antigua.

## 2.2 Estructura de directorios en GNU/Linux (FHS)

La mayoría de distribuciones siguen el estándar **FHS** (*Filesystem Hierarchy Standard*), que define el contenido y la función de cada directorio.

| Directorio | Función |
| :-: | --- |
| `/` | Raíz; de él parten todos los directorios. |
| `/root` | *Home* del superusuario. Separado de `/home` para que el administrador pueda entrar aunque `/home` falle o no se monte. |
| `/bin` | Binarios (ejecutables) de usuario. |
| `/sbin` | Ejecutables para el mantenimiento del sistema que solo debería usar root (`iptables`, `fdisk`, `reboot`). |
| `/boot` | Ejecutables y configuración necesarios para el arranque. |
| `/lib` | Librerías y módulos del kernel, que necesitan, por ejemplo, los programas de `/bin` y `/sbin`. |
| `/usr` | La mayoría de aplicaciones, binarios y librerías instalados por el gestor de paquetes no críticos para el arranque mínimo. En muchas distribuciones `/bin` es un enlace simbólico a `/usr/bin`. |
| `/home` | Directorios personales de los usuarios (salvo root). |
| `/proc` | Información de procesos y kernel. Archivos **virtuales** generados sobre la marcha; vive en la RAM. |
| `/sys` | Archivos virtuales del kernel sobre **drivers y dispositivos**. |
| `/dev` | Componentes y dispositivos representados como archivos (flash, particiones, DVD…). Ver [[Sistemas Informáticos/Unidad 3 Sistemas operativos. Gestión de archivos y almacenamiento/Apuntes/4. Montaje, particionado y formateo#4.1 Nombres de dispositivos en Linux\|nombres de dispositivos]]. |
| `/etc` | Archivos de configuración del SO y de los programas instalados. |
| `/media` | Montaje automático de medios (discos, USB, CD/DVD). |
| `/mnt` | Puntos de montaje **temporales** usados manualmente por el administrador (ISO, carpetas compartidas de una MV…). |
| `/tmp` | Archivos temporales de las aplicaciones. |
| `/srv` | Datos, scripts y carpetas de servidores (web, FTP, repositorios…). |
| `/var` | "Registro" del sistema: logs, datos de las aplicaciones, cola de impresión, etc. |

## 2.3 Estructura de directorios en Microsoft Windows

Windows tiende a agrupar según **programa** o **usuario**. Raíz de la partición con Windows:

| Carpeta | Función |
| --- | --- |
| `\Archivos de programa` (`Program Files`) | En 32 bits, todos los programas; en 64 bits, las aplicaciones de 64 bits. |
| `\Archivos de programa (x86)` | Solo en sistemas de 64 bits: aplicaciones de 32 bits, para que no carguen DLL de 64 bits (error inmediato). |
| `\PerfLogs` | Vacía por defecto; puede contener registros de rendimiento. |
| `\ProgramData` | Oculta; datos de programas comunes a todos los usuarios. |

> [!question] Lista incompleta
> La fuente no describe otras carpetas de la raíz como `\Windows` o `\Users` (Usuarios).

> [!info] Fuentes
> - [Microsoft Learn: KNOWNFOLDERID (FOLDERID_ProgramData = `%ALLUSERSPROFILE%`, `C:\ProgramData`)](https://learn.microsoft.com/en-us/windows/win32/shell/knownfolderid)

> [!note] DLL (bibliotecas de vínculos dinámicos)
> Archivos con código ejecutable o datos. Aumentan la modularidad, ahorran recursos y simplifican la instalación. Inconvenientes, porque muchos programas comparten las mismas DLL y estas evolucionan perdiendo compatibilidad:
> - Instalar un programa puede **reemplazar una DLL** por una versión incompatible.
> - Desinstalar un programa puede **borrar una DLL compartida**.

## 2.4 Moverse entre directorios en Linux

Sintaxis: `cd [directorio]` (*change directory*).

```bash
cd            # ir al directorio personal (también: cd ~)
cd ..         # subir al directorio padre (también: cd ./..)
cd -          # alternar entre los dos últimos directorios
cd /home/user # ir a un directorio concreto
pwd           # mostrar el directorio actual
```

> [!warning] Falta fuente: movimiento entre directorios en la consola de Windows
> La fuente solo indica que `cd` sin argumentos muestra el directorio actual en Windows. No trae más comandos de CMD ni PowerShell.
