# Unidad 3: Sistemas operativos. Gestión de archivos y almacenamiento

> [!abstract] Criterios que se trabajan
> **CE3E** (realizar y restaurar copias de seguridad) y **CE3G** (utilidades: Clonezilla, GParted, `tar`). Contenido **BC3_5**. Fuente: Tema 7, apartado 6 (§6.1 y §6.2).

## 8.1 Para qué sirven

Herramientas para:

- Copia de seguridad de todo el sistema.
- Aseguramiento de los datos.
- Recuperación, reinicio y restauración.

Causas por las que hay que restaurar:

- Errores irrecuperables del sistema operativo.
- Eliminaciones o accesos malintencionados.
- Mal funcionamiento de una aplicación.
- Rotura de un medio de almacenamiento o inconsistencia de sus datos.
- Descuidos personales.
- Malware.

## 8.2 Clonaciones

Copian los datos de particiones o discos a otras particiones o medios creando una **réplica exacta**: sistema operativo, aplicaciones y datos quedan duplicados.

Funcionan creando una **imagen**: un archivo o conjunto de archivos con la estructura y el contenido del origen.

> [!note] Precauciones
> - Los discos implicados **no pueden estar en funcionamiento**, así que la clonación debe **planificarse**.
> - Tras clonar un disco con SO hay que **configurar el "nuevo sistema"** (arranque, red, usuarios, licencias…) para evitar duplicidades que generen errores.

Software libre de clonación: **GParted** y **Clonezilla**. La web de Clonezilla ofrece tutoriales de sus versiones:

| Versión | Uso |
| --- | --- |
| **Clonezilla live** | Una sola máquina. |
| **Clonezilla SE** y **Clonezilla lite server** | Clonar más de 40 equipos simultáneamente en red. |

## 8.3 Copias de seguridad

A diferencia de las clonaciones, manejan **archivos concretos**, lo que facilita su **restauración individual**.

Las **políticas de *backup*** determinan:

- La **frecuencia** de las copias.
- El **conjunto de archivos** que se copian.
- El **soporte** de *backup*.
- El **tipo** de copia.

| Tipo | Qué copia |
| --- | --- |
| **Total** | Todos los archivos seleccionados. |
| **Incremental** | Los archivos cambiados desde la última copia **total o incremental**. |
| **Diferencial** | Los archivos cambiados desde la última copia **total**. |

## 8.4 Copias por comandos en Linux: `tar`

`tar` empaqueta archivos en un **contenedor** (archivo que contiene otros archivos o carpetas).

| Opción | Efecto |
| :-: | --- |
| `c` | Crea un contenedor. |
| `x` | Extrae (restaura) desde el contenedor. |
| `f contenedor` | Crea o lee el contenedor indicado. |
| `z` | Comprime/descomprime con **gzip**. |
| `j` | Comprime/descomprime con **bzip2**. |
| `t` | Lista el contenido. |
| `v` | Detalla las acciones. |
| `C directorio` | Cambia a ese directorio antes de actuar. |

> [!tip] Nombres
> Al comprimir con gzip añadir `.tgz` y con bzip2 `.tbz` al nombre del contenedor.

Ejemplos de la fuente (las órdenes están en capturas; se reconstruyen con las opciones anteriores):

```bash
# Empaquetar dos archivos en "almacen", borrarlos, ver el contenido y extraerlos
tar -cvf almacen archivo1 archivo2
rm archivo1 archivo2
tar -tvf almacen
tar -xvf almacen

# Comprimir con gzip /home/luis y restaurarlo en dir_respaldo
tar -czvf backup.tgz /home/luis
mkdir dir_respaldo
tar -xzvf backup.tgz -C dir_respaldo
ls dir_respaldo
```

> [!note] Nombre del contenedor
> Un contenedor comprimido con **gzip** se nombra `.tgz` (o `.tar.gz`); con bzip2, `.tbz` (o `.tar.bz2`). Aquí se usa `backup.tgz`.

### 8.4.1 Fecha en el nombre: `date`

Conviene incluir en el nombre de la copia la **fecha** y el **tipo** de copia. `date` muestra la fecha con el formato indicado (ver `man date`). Para insertarla en una cadena se encierra la orden entre acentos graves `` `date` `` o en `$( )`.

```bash
tar -czvf total_$(date +%Y%m%d).tgz /home/luis   # p. ej. total_20261001.tgz
```

### 8.4.2 Copia incremental con `tar`

1. Hacer una copia **total** generando un archivo de **metadatos** con `-g`.
2. Hacer las **incrementales** con el **mismo** archivo de metadatos: solo se guardan los archivos modificados respecto a él.

```bash
tar -czvf total.tgz -g metadatos.snar /home/luis/Documentos
tar -czvf incremental1.tgz -g metadatos.snar /home/luis/Documentos
```

En el ejemplo de la fuente, tras crear `nuevoDocumento.txt`, solo ese archivo entra en la incremental.

**Restauración:** se restauran la total y las incrementales **en el mismo orden**, con la opción **`-G`** (reposición incremental).

```bash
tar -xzvf total.tgz -G
tar -xzvf incremental1.tgz -G
```

Las órdenes de la fuente están en capturas; las de arriba se reconstruyen a partir del texto y se han comprobado con GNU tar (el nombre `metadatos.snar` es libre). Para restaurar, el manual de GNU tar también admite `-g /dev/null` en lugar de `-G`.

### 8.4.3 Copia diferencial respecto a una fecha

`tar` con **`-N fecha`** (`--newer`) guarda los archivos cuya fecha de **modificación (mtime) o de cambio de estado (ctime)** es más reciente que la fecha (`--newer-mtime` compara solo mtime). Los directorios se incluyen siempre. Ejemplo de la fuente: archivos de `/home/Luis/Documentos` cuyo ctime cambió desde el 14 de mayo de 2019.

```bash
tar -czvf diferencial.tgz -N 2019-05-14 /home/Luis/Documentos
```

> [!info] Fuentes
> - [GNU tar: Incremental dumps](https://www.gnu.org/software/tar/manual/html_node/Incremental-Dumps.html) y [Operating only on new files (`--newer`)](https://www.gnu.org/software/tar/manual/html_node/after.html)

## 8.5 Copias por interfaz gráfica en Windows

### 8.5.1 Copia de seguridad de archivos

Ruta (Windows 10): **Configuración → Actualización y seguridad → Copia de seguridad**. En Windows 11 esta página desaparece: se usa la aplicación **Copia de seguridad de Windows** (sincroniza con OneDrive) y el **Historial de archivos** queda en el Panel de control.

1. **Agregar una unidad** para guardar la copia (distinta de la de instalación de Windows).
2. **Más opciones:** frecuencia, duración (conservación), carpetas (por defecto, las de la cuenta del usuario) y configuración avanzada.
3. La **configuración avanzada** abre el **Historial de archivos** del Panel de control, con opciones más concretas.

### 8.5.2 Copia de imagen del sistema

Crea una copia de los archivos del SO como una **instantánea**.

1. **Panel de control → Copias de seguridad y restauración (Windows 7) → Crear una imagen de sistema.**
2. Destino: disco duro (sin espacio reservado o usado por el SO), DVD o unidad de red.
3. **Siguiente → Iniciar la copia de seguridad.**
4. Al terminar, ofrece **crear un disco de reparación del sistema** (siempre recomendable): arrancando desde él se accede a un menú de opciones de recuperación.

> [!warning] Falta fuente: copias por comandos en Windows y copias gráficas en Linux
> El Tema 7 no trae comandos de Windows (`wbadmin`, `robocopy`…) ni herramientas gráficas de Linux (p. ej. Snapper/YaST en openSUSE). Tampoco detalla la **restauración** desde la interfaz de Windows.
