# Unidad 6: Gestión de recursos en red de un sistema informático

> [!abstract] Criterios que se trabajan
> **CE6C** (servidores de ficheros, de impresión y de aplicaciones). Contenidos **BC6_4**, **BC6_5** y **BC6_6**.

## 4.1 Servidores: características

Los servidores permiten **compartir recursos en red**. Un servidor hardware soporta el sistema operativo y el software que comparte los recursos, y debe cumplir:

| Aspecto | Significado |
| :-: | --- |
| **Disponibilidad** | Activo y funcionando el máximo tiempo posible para que los recursos estén accesibles. |
| **Escalabilidad** | Permite crecer al aumentar la demanda de trabajo. |
| **Mantenimiento** | Admite tareas de mantenimiento sin mermar la disponibilidad. |

> [!note] Modelo cliente-servidor
> El servidor ofrece servicios a varios clientes: queda a la espera de peticiones y responde a cada una.

## 4.2 Servidor de ficheros (FTP)

**Objetivo:** gestionar el almacenamiento controlado de ficheros para distintos clientes. Centralizar los ficheros facilita compartirlos, gestionar permisos de acceso, registrar conexiones, hacer copias de seguridad y controlar versiones.

| Protocolo | Descripción |
| :-: | --- |
| **FTP** | *File Transfer Protocol*. Puerto **21**. |
| **FTPS** | FTP sobre SSL/TLS (datos cifrados; hoy se usa TLS). |
| **SFTP** | *SSH File Transfer Protocol*: protocolo distinto de FTP que funciona sobre SSH (puerto **22**). |

### 4.2.1 Servidor FTP en Windows (IIS)

**Instalación:**

1. **Panel de control** → **Programas y características** → **Activar o desactivar las características de Windows**.
2. Expandir **Internet Information Services** y activar **Servidor FTP** y **Herramientas de administración web**.
3. Aceptar: comienza la instalación.

**Configuración del sitio FTP:**

1. **Herramientas administrativas** → **Administrador de Internet Information Services (IIS)**.
2. Panel **Conexiones**: clic secundario en **Sitios** → **Agregar sitio FTP**. Indicar **nombre** del sitio y **ruta** de la carpeta a la que accederán los clientes.
3. **Enlace**: mantener la configuración. **SSL**: **Sin SSL** en la práctica (en un entorno corporativo es muy recomendable **requerir SSL**).
4. **Autenticación**: **Básica**; **autorización** a usuarios o grupos (en el ejemplo, dos usuarios con lectura y escritura).
5. Finalizar: el sitio aparece en el panel de conexiones.

> [!warning] Cortafuegos y acceso externo
> - El firewall puede bloquear el FTP: **Panel de control** → **Firewall de Windows Defender** → **Permitir una aplicación o una característica a través de Firewall de Windows Defender** → habilitar **Servidor FTP**.
> - Para acceder desde fuera de la red interna: asignar al servidor una **IP estática** y configurar en el router (*gateway*) la **redirección de puertos** (*Port Forwarding*) del puerto **21**.

### 4.2.2 Cliente FTP

- **Explorador de archivos** de Windows: escribir `ftp://direccionIP` y, a continuación, las credenciales de un usuario con permiso.
- **Aplicaciones cliente**, que reúnen más herramientas: la más usada es **FileZilla Client** (https://filezilla-project.org), de interfaz sencilla.

> [!warning] Falta fuente: servidor de ficheros en Linux
> El Tema 6 no explica cómo montar un servidor FTP/SFTP en Linux. Como servidor de ficheros Linux, ver Samba en [[Sistemas Informáticos/Unidad 6 Gestión de recursos en red de un sistema informático/Apuntes/2. Recursos compartidos en Windows y Samba#2.2 Compartir en Linux: Samba\|Samba]].

## 4.3 Servidor de impresión

**Objetivo:** dar conectividad con impresoras sin depender de ningún *host*: se conectan directamente a la red y hacen de enlace con las impresoras.

| Tipo | Ubicación |
| :-: | --- |
| **Externo** | Fuera de la impresora, conectado a un puerto de esta. |
| **Interno** | Dentro de la impresora. |

### 4.3.1 Servidor de impresión en Windows

Los servidores de impresión **hardware** traen su propia guía de instalación. Las versiones avanzadas de Windows incluyen **Administración de impresión** para gestionar impresoras de forma centralizada y actuar como servidor.

> [!note] Requisitos
> - El equipo servidor debe estar **encendido**.
> - Al conectar, los usuarios deben estar **activos** y tener **contraseña**.
> - Todos en la **misma red**.
> - Habilitadas la **detección de redes** y el **uso compartido de archivos e impresoras** en **Configuración de uso compartido avanzado**.

Configuración:

1. **Herramientas administrativas** → **Administración de impresión**.
2. Clic secundario sobre la impresora → **Propiedades**.
3. Pestaña **Compartir**: **Compartir esta impresora** e indicar el nombre del recurso.
4. Pestaña **Seguridad**: permisos de usuarios y grupos sobre la impresora.
5. Pestaña **Opciones avanzadas**: **disponibilidad** (horario concreto) y cuándo **empezar a imprimir**.

La centralización permite además:

- **Agregar drivers** según la arquitectura del SO cliente, para que los clientes nuevos usen la impresora sin instalarlos.
- **Agregar más impresoras**.
- Cambiar la carpeta de la **cola de impresión**.

### 4.3.2 Clientes de impresión (Windows)

1. **Configuración** → **Impresoras y escáneres** → **Agregar una impresora o un escáner**.
2. Si no aparece: **La impresora que deseo no está en la lista**.
3. Indicar el acceso al recurso compartido (por ejemplo, **Seleccionar una impresora compartida por nombre**, `\\servidor\impresora`).
4. Introducir las credenciales de un usuario con privilegios.

> [!warning] Falta fuente: impresión en red en Linux
> El Tema 6 no trata el servidor/cliente de impresión en Linux (CUPS, impresoras Samba).

## 4.4 Servidor de aplicaciones

**Objetivo:** alojar y ejecutar programas a petición de los clientes a través de la red. Gestionan la **lógica de negocio** de la aplicación, abstrayendo y centralizando sus operaciones. Sirven para:

- Reducir la complejidad y el tamaño de las aplicaciones cliente.
- Dirigir el flujo de datos para aumentar el rendimiento.
- Controlar la seguridad de los datos.

| Servidor | Notas |
| --- | --- |
| **WebLogic** | De Oracle (propietario). |
| **Zope** | En Python, código abierto. |
| **WildFly** | Servidor de aplicaciones web Java. |
| **Apache Geronimo** | De Apache; sin desarrollo activo. |
| **GlassFish** | Hoy **Eclipse GlassFish** (Fundación Eclipse). |

> [!info] Fuentes
> - [WildFly](https://www.wildfly.org/) (antes JBoss AS, de Red Hat) · [Eclipse GlassFish](https://glassfish.org/) · [Oracle WebLogic](https://www.oracle.com/java/weblogic/) · [Zope](https://www.zope.dev/)

### 4.4.1 Arquitectura en tres capas

| Nivel | Capa | Función |
| :-: | --- | --- |
| 1 | **Presentación** (GUI del cliente) | Los usuarios se conectan al servidor, normalmente con un navegador web u otra aplicación cliente. |
| 2 | **Aplicación** (servidor de aplicaciones) | Ejecuta y procesa la información; intermediario entre clientes y datos. |
| 3 | **Datos** | Aloja los datos necesarios para atender las peticiones. |

> [!warning] Falta fuente: instalación de un servidor de aplicaciones
> El Tema 6 no incluye ninguna práctica de instalación o explotación de servidores de aplicaciones.
