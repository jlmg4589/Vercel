# Unidad 2: Sistemas operativos. Introducción

> [!abstract] Criterios que se trabajan
> **CE2B** (características y funciones de un sistema operativo). Contenido **BC2_2**.

## 2.1 Qué es un sistema operativo

Según el Tema 1, por sistema operativo se entiende:

- El software que actúa de **interfaz entre usuario y hardware**.
- El software que **gestiona** efectivamente los **recursos hardware y software** del sistema de forma transparente para el usuario.
- El conjunto de programas que facilitan la interacción del usuario con la máquina aprovechando todos sus recursos.

No es un programa aislado y único, sino un **núcleo de módulos** que interaccionan entre sí. Está sometido a un avance continuo por los cambios de hardware y software y para evitar problemas de seguridad.

El SO se inicia justo **después del POST**, durante el arranque del ordenador (ver [[Sistemas Informáticos/Unidad 1 Fundamentos de los sistemas informáticos/Apuntes/5. Puesta en marcha del equipo. POST\|5. Puesta en marcha del equipo. POST]] y [[Sistemas Informáticos/Unidad 2 Sistemas operativos. Introducción/Apuntes/6. Arranque del sistema operativo y gestores de arranque\|6. Arranque del sistema operativo y gestores de arranque]]).

## 2.2 Funciones

**Funciones básicas** (visión general):

1. Actuar de **interfaz** entre el usuario y el hardware, de forma transparente para el usuario.
2. **Gestionar los recursos** software (aplicaciones) y hardware (cada parte del PC).

**Funciones concretas:**

- Controlar y administrar el **sistema de archivos**.
- Gestionar los **procesos**.
- Gestionar la **memoria**.
- Gestionar los **usuarios**.
- Mantener y controlar la **seguridad**.
- Gestionar el sistema de **entradas y salidas**.
- Gestionar los **errores**.

> [!note] Servidores sin interfaz gráfica
> Los SO de servidor no suelen incorporar interfaz gráfica: consumen menos recursos, por lo que rinden mejor, los comandos se ejecutan más rápido y son más seguros.

## 2.3 Características

| Característica | Descripción |
| --- | --- |
| **Adaptabilidad** | Adaptarse (normalmente con actualizaciones) a nuevos requisitos hardware y software para aprovechar nuevas características o mejoras. |
| **Facilidad de uso** | Primordial para el usuario medio. Más comodidad suele implicar más recursos; hay SO que ganan eficiencia restringiendo su manejabilidad. |
| **Eficiencia** | Los recursos son limitados: el SO debe atender, **marcando prioridades**, las peticiones del usuario, de los programas y del propio SO, siendo selectivo en sus decisiones. |

El propio SO es software y también **consume recursos**, normalmente muchos en comparación con el software de un usuario común.

## 2.4 Recursos que gestiona

| Recurso | Importancia de su gestión |
| --- | --- |
| **Memoria RAM** | La parte del SO que **siempre reside en RAM** es el **núcleo o kernel**. El resto de módulos se cargan y descargan desde el almacenamiento secundario. |
| **Procesador** | Uno de los recursos más limitados: interpreta y ejecuta cada línea de código de cualquier programa. |
| **Adaptadores de red** | Varias aplicaciones usan la red a la vez: hay que administrar las conexiones entre aplicaciones, procesos y usuarios. |
| **Medios de almacenamiento** | El acceso a disco puede ser un **cuello de botella** importante. |
| **Colas de impresión** | Las peticiones de impresión pueden llegar en paralelo; se ordenan en colas. |

## 2.5 Administración del sistema

### 2.5.1 Gestión de procesos

Un **proceso** es, de forma resumida, un **programa en ejecución** en un momento determinado. El procesador debe repartir su tiempo entre los procesos que quieren ejecutarse.

El **planificador** del SO controla y optimiza la ejecución: decide qué proceso usa la CPU, establece y modifica el estado de cada proceso según un **algoritmo de planificación** (ver [[Sistemas Informáticos/Unidad 2 Sistemas operativos. Introducción/Apuntes/3. Algoritmos de planificación de procesos\|3. Algoritmos de planificación de procesos]]), que asigna un tiempo de ejecución o ***quantum*** a los procesos que ocupan la CPU. Al acabar el *quantum* se genera una **interrupción de reloj**, el SO recupera el control y el planificador toma el siguiente proceso de la **cola de listos** según su algoritmo (prioridades).

**Estados de un proceso:**

| Estado | Descripción |
| --- | --- |
| **Nuevo** | Se crean las estructuras de datos para gestionarlo y se le asigna memoria. La más representativa es el **PCB** (bloque de control de proceso). |
| **Listo o preparado** | Cargado en memoria, esperando pasar a ejecución. |
| **Ejecución** | Está usando la CPU. |
| **Bloqueado** | Necesita un recurso o espera un evento. Cuando el recurso está disponible o llega el evento, vuelve a **listo**. |
| **Terminado** | Ejecución completa. Se liberan sus recursos y se eliminan sus estructuras (como el PCB). |

![Estados de un proceso.png](/img/user/Sistemas%20Inform%C3%A1ticos/03_Recursos/Imagenes/Unidad%202/Estados%20de%20un%20proceso.png)

**Cambio de contexto:** al pasar la CPU de un proceso a otro, el SO guarda el estado del proceso saliente (registros, contador de programa…) en su **PCB** y carga desde el PCB del entrante su estado guardado. Durante el cambio la CPU no hace trabajo útil, por lo que es una **sobrecarga** que conviene minimizar.

![Cambio de contexto.png](/img/user/Sistemas%20Inform%C3%A1ticos/03_Recursos/Imagenes/Unidad%202/Cambio%20de%20contexto.png)

> [!info] Fuentes
> - [Wikipedia – Context switch](https://en.wikipedia.org/wiki/Context_switch)

**Eventos que provocan las transiciones:** interrupción de temporizador o de E/S completada, llamada al sistema, finalización del proceso (`exit()`), o excepción/fallo (operación no permitida, uso de recursos no autorizados…).

El SO debe gestionar:

1. La asignación de procesos a varios procesadores (si los hay).
2. La **multiprogramación** sobre procesadores individuales y sus núcleos.
3. La ejecución sincronizada de un proceso con otros procesos o hilos.

| Orientación de la planificación | Objetivo |
| --- | --- |
| **A los usuarios** (orientada a E/S) | Prima el **tiempo de respuesta**: agiliza las acciones del usuario a través de sus interfaces. |
| **Al sistema** (orientada a cálculo) | **Eficiencia y rendimiento** de procesamiento; el sistema se ralentiza con mucha carga de cálculo. |

> [!note] Definiciones
> - **Multiprogramación:** cargar varios programas en memoria principal para incrementar el uso de la CPU.
> - **DMA (acceso directo a memoria):** proceso que accede a la memoria principal **sin intervención de la CPU**.

### 2.5.2 Gestión de memoria

Planificación y gestión global de la memoria principal, con extensión a la secundaria. Si hace falta más espacio, se amplía virtualmente la RAM tomando prestado espacio del disco: **memoria virtual**. El SO gestiona el intercambio y la zona de **intercambio/paginación (*swap*)**, descargando procesos no activos para liberar memoria para otros.

### 2.5.3 Gestión de entradas y salidas

Administra los recursos de los dispositivos de E/S, ofreciendo soluciones rápidas y lo menos costosas posible.

### 2.5.4 Gestión de almacenamiento secundario

La gestión de los datos de los discos (archivos y directorios) la determinan los **sistemas de archivos**: NTFS, FAT16, FAT32, ext3, ext4… Se amplía en la UD3: [[Sistemas Informáticos/Unidad 3 Sistemas operativos. Gestión de archivos y almacenamiento/Apuntes/1. Sistemas de archivos#1.8 Comparativa\|Sistemas de archivos]].

### 2.5.5 Gestión de la seguridad

Evitar inconsistencias por errores software, hardware o acciones maliciosas. Debe garantizar:

- El servicio y la **disponibilidad** de los recursos.
- La **confidencialidad**, protección e **integridad** del sistema y los datos.
- El **control de accesos**.
- La **autenticidad** de las acciones.

### 2.5.6 Gestión de errores

Gestionar todo tipo de errores de la manera más liviana posible, **informando al usuario** y salvaguardando prioritariamente la seguridad del sistema y los datos.

### 2.5.7 Gestión de la interfaz de usuario

Los SO con interfaz gráfica o textual deben ofrecer un soporte que permita una comunicación fluida y realizar todas las acciones de gestión, administración o explotación.
