# Unidad 2: Sistemas operativos. Introducción

> [!abstract] Criterios que se trabajan
> **CE2G** (tecnologías de virtualización para instalar y probar SO) y **CE2F** (instantáneas como técnica de recuperación). Contenido **BC2_8**.

## 7.1 Virtualización

Tipos de virtualización: de **datos**, de la **plataforma** (hardware o servidor), de las **aplicaciones** y de los **sistemas operativos**. Su uso está muy extendido entre particulares y empresas.

La **virtualización por hardware** permite crear varios entornos virtuales en un mismo equipo físico: **máquinas virtuales** independientes, cada una con su propio SO.

Ventajas:

- **Reduce costes:** menos hardware; un equipo ejecuta varias MV de distintos usuarios.
- **Seguridad:** cada máquina se ejecuta aislada del resto.
- **Flexibilidad:** crear, modificar y configurar MV es más fácil que con equipos físicos.
- Ejecutar **varios SO** en un mismo equipo.
- **Probar un SO** antes de instalarlo en una máquina física.

## 7.2 Tipos de virtualización del hardware

El **hipervisor** es el software de virtualización. Se clasifica según dónde se ejecute:

| Tipo | Nombre | Dónde se instala |
| :-: | --- | --- |
| **1** | Nativa o *bare metal* | Directamente sobre el **hardware**. Al arrancar se carga el hipervisor, que incorpora un SO de administración. |
| **2** | Hospedada | Sobre un **SO ya instalado**. El SO físico es el **anfitrión (*host*)** y el de la MV, el **invitado (*guest*)**. |
| **Híbrida** | — | Se ejecuta sobre un SO (como el tipo 2) pero puede interactuar directamente con el hardware (como el tipo 1). |

## 7.3 Hipervisores de escritorio

| Hipervisor | Tipo | Empresa | Anfitriones |
| --- | :-: | --- | --- |
| VMware Workstation Player | 2 | VMware | Windows, Linux (en macOS: **VMware Fusion**) |
| Hyper-V | 1 | Microsoft | Windows Server, Windows 10/11 Pro, Enterprise y Education |
| Oracle VM VirtualBox | 2 | Oracle | Windows, macOS, Linux, Solaris |

### 7.3.1 VMware Workstation Player

Producto de introducción a la virtualización. La fuente cita una versión de uso **no comercial** y una versión **Pro** con funciones avanzadas; desde 2024 (VMware pertenece a Broadcom) **Player se ha suprimido** y **Workstation Pro es gratuito para cualquier uso** (desde el 11/11/2024). Para servidores y nube (tipo 1), VMware ofrece **ESXi** (vSphere Hypervisor), vSphere y VMware Cloud Foundation; *VMware Server*, que cita la fuente, se abandonó en 2011. Todos traen una herramienta para ejecutar contenedores o clústeres de contenedores locales.

### 7.3.2 Hyper-V (Windows)

Hipervisor de tipo 1 de Microsoft. **No está disponible en Windows Home.**

Activación: *Panel de control → Programas y características → Activar o desactivar las características de Windows*, marcar **Hyper-V** y **Aceptar**.

Otras características que se pueden activar en ese panel:

| Característica | Para qué sirve |
| --- | --- |
| **Contenedores** | Crear y administrar contenedores de Windows Server. |
| **Plataforma de hipervisor de Windows** | Permite ejecutar hipervisores de tipo 2 y Docker junto a Hyper-V. En VirtualBox hay que cambiar la **interfaz de paravirtualización** a Hyper-V en *Configuración → Sistema → Aceleración* (la fuente dice, por errata, "sistema / actualización"). |
| **Plataforma de máquina virtual** | Necesaria para **WSL2**. |
| **Subsistema de Windows para Linux** | Usar, por ejemplo, Ubuntu como una aplicación más de Windows. |

### 7.3.3 Oracle VM VirtualBox

Hipervisor de tipo 2, muy utilizado, con licencia **GNU GPL v3**. Soporta gran cantidad de SO invitados. Es el que se usa en el aula (sobre openSUSE).

| Extensión | Dónde se instala | Aporta |
| --- | --- | --- |
| **Extension Pack** | En el anfitrión, tras instalar VirtualBox (se descarga de su web). Licencia **PUEL**, no GPL | En VirtualBox 7.x: servidor de escritorio remoto (**VRDP**), *webcam* del anfitrión, ROM de arranque **PXE** Intel (desde la red), cifrado de discos e integración con Oracle Cloud. USB 2.0/3.0 y NVMe, que cita la fuente, ya vienen en el paquete base. |
| **Guest Additions** | **Dentro de cada SO invitado** (la fuente dice, por errata, "anfitrión") | Integración del ratón, carpetas compartidas, portapapeles compartido, arrastrar y soltar, sincronización horaria, ajuste automático de la resolución… |

> [!warning] Misma versión
> El Extension Pack debe tener **la misma versión** que VirtualBox; si se actualiza VirtualBox, hay que actualizar también el Extension Pack.

#### Tecla anfitrión (*host*)

Por defecto es **Ctrl derecho**.

| Acción | Cómo |
| --- | --- |
| Liberar el ratón (sin integración) | Tecla host |
| Con integración del ratón | Basta hacer clic fuera de la MV. Desactivarla: *Entrada → Integración del ratón* |
| Enviar Ctrl+Alt+Supr al invitado | **Host+Supr** o *Entrada → Teclado → Insertar Ctrl+Alt+Del* |
| Cerrar la MV | **Host+Q** |

#### Crear una máquina virtual

*Máquina → Nueva…* (**Ctrl+N**) o icono **Nueva**. Se elige entre **modo guiado** (pantallas sucesivas) y **modo experto** (todo en una ventana); se alterna con el botón correspondiente.

**Modo guiado:**

1. **Nombre**, carpeta (**Folder**), **Tipo** y **Versión** del SO. En **ISO Image**, la imagen del SO (se puede añadir después).
2. ***Skip Unattended Installation***: si se marca, la instalación será **interactiva**. Si hay ISO y se deja desmarcada (**instalación desatendida**), se piden: **Username**, **Password**, **Product Key** (se puede dejar el valor por defecto), **Hostname** (sin espacios) y **Domain Name**. Opciones:
   - ***Install in Background***: instalación en segundo plano, sin interfaz gráfica.
   - ***Guest Additions***: se instalan durante la instalación del SO.
3. **Hardware:** **Memoria base** (MB de RAM), **Processors** (CPU virtuales) y si se habilita el arranque **EFI**.
4. **Virtual hard disk:** usar uno existente, no añadir disco o crear uno nuevo (por defecto **VDI** con el nombre de la MV). ***Pre-allocate Full Size***: desmarcada, **reserva dinámica** (ocupa a medida que se usa); marcada, **tamaño fijo** (ocupa todo desde el principio, acceso más rápido).
5. **Resumen:** *Atrás* para cambiar algo o *Terminar*. Siempre se puede modificar después en la configuración.

**Modo experto:** las mismas opciones en una ventana, y además la ubicación y tamaño del disco y su **formato**:

| Formato | Uso |
| :-: | --- |
| **VDI** | Predeterminado de VirtualBox |
| **VHD** | Hyper-V |
| **VMDK** | VMware; permite dividir el disco en ficheros de 2 GB |
| **HDD** | Parallels Desktop (macOS) |
| **QCOW / QED** | QEMU y otros |

Al pulsar *Terminar*: si es **desatendida**, comienza la instalación (atención por si pide pulsar una tecla para arrancar desde CD/DVD); si no, hay que pulsar **Iniciar**.

#### Operaciones sobre una máquina existente

| Operación | Menú / atajo | Descripción |
| --- | --- | --- |
| **Configuración** | *Máquina → Configuración…* (Ctrl+S) | Nombre y hardware. En *Sistema → Placa base*: memoria y **orden de arranque**; pestaña *Procesador*. |
| **Clonar** | *Máquina → Clonar…* (Ctrl+O) | Nombre, ruta, política de **MAC**, nombres de disco y **UUID** (conviene cambiarlos si será independiente). Clonación **completa** (independiente) o **enlazada** (discos vinculados al original). |
| **Instantáneas (*snapshots*)** | *Máquina → Herramientas → Instantáneas*, **Tomar instantánea** (Ctrl+Mayús+T) | **Punto de restauración** al que volver si hay un fallo. |
| **Iniciar / Pausar / Reiniciar** | — | Arranca, pausa o reinicia la MV. |
| **Cerrar** | *Archivo → Cerrar* (Host+Q) | **Guardar el estado**, **Enviar señal de apagado** o **Apagar** (puede perder datos; solo si falla lo demás). |
| **Descartar** | *Máquina → Descartar el estado guardado…* | Elimina el último estado guardado (se pierde esa información). |
| **Eliminar** | *Máquina → Eliminar…* o botón derecho | Solo la máquina o también sus archivos. |

**Preferencias:** *Archivo → Preferencias…* (Ctrl+G): carpeta predeterminada de las MV (*General*), comprobación de **actualizaciones** y su frecuencia, idioma, pantalla…
