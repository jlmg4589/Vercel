# Unidad 4: Sistemas operativos. Gestión de usuarios y procesos

> [!abstract] Criterios que se trabajan
> **CE4C** (identificar, arrancar y detener servicios) y **CE4E** (comandos). Contenidos **BC4_5** y **BC4_6**.

## 5.1 Servicios en Linux. systemd

Un **servicio** es un proceso que se ejecuta en segundo plano esperando a que un usuario u otro proceso lo llame. En Linux se llaman **daemons** (demonios), acrónimo de *Disk and Execution Monitor*.

**systemd** gestiona los procesos durante el arranque y los servicios a lo largo de su vida. Se maneja con **`systemctl`**, que gestiona las **unidades** de systemd: servicios, dispositivos, objetivos de inicio, temporizadores, etc.

```text
systemctl [opciones...] comandos...
```

| Comando | Función |
| --- | --- |
| `sudo systemctl start <servicio>` | Inicia. |
| `sudo systemctl stop <servicio>` | Para. |
| `sudo systemctl restart <servicio>` | Reinicia. |
| `sudo systemctl reload <servicio>` | Recarga la configuración sin pararlo. |
| `sudo systemctl enable <servicio>` | Lo habilita en el arranque (no lo inicia ahora salvo con `--now`). |
| `sudo systemctl disable <servicio>` | Lo deshabilita en el arranque. |
| `systemctl status <servicio>` | Muestra el estado (a veces requiere `sudo`; se sale con `q`). |
| `systemctl is-active <servicio>` | Indica si está activo. |

Colores de `status`:

| Color | Estado |
| :-: | --- |
| Blanco | Inactivo o desactivado. |
| Rojo | Fallo o error. |
| Verde | Activo, activándose o recargándose. |

## 5.2 Ejemplo: servicio DHCP en Ubuntu

1. Instalar el paquete:
   ```bash
   sudo apt install isc-dhcp-server
   ```
2. Indicar la interfaz en `/etc/default/isc-dhcp-server`: `INTERFACES="XXXX"` (el nombre se obtiene con `ifconfig`, del paquete `net-tools`).
3. Configurar `/etc/dhcp/dhcpd.conf`:
   ```text
   subnet 192.168.56.0 netmask 255.255.255.0 {
     range 192.168.56.20 192.168.56.100;
     option routers 192.168.56.1;
     option domain-name-servers 8.8.8.8, 8.8.4.4;
     filename "pxelinux.0";
   }
   ```
4. Forzar la IP del servidor, primero manualmente y después por comando:
   ```bash
   sudo ifconfig [tarjeta de red] [IP del servidor] netmask [máscara de red]
   ```
5. Reiniciar el servicio y comprobar su estado:
   ```bash
   sudo systemctl restart isc-dhcp-server
   sudo systemctl status isc-dhcp-server
   ```

> [!tip]
> La configuración de red y el servicio DHCP se amplían en la [[Sistemas Informáticos/Unidad 5 Sistemas informáticos en red. Configuración y explotación/Apuntes/3. Configuración TCP-IP del cliente y ficheros de red#3.2 Configuración dinámica (DHCP)\|UD5]].

> [!warning] Falta fuente: openSUSE
> En openSUSE el paquete, la ruta de configuración y la instalación (`zypper`, YaST) son distintos; no hay fuente sobre ello.

## 5.3 Servicios en Windows (interfaz gráfica)

- **Servicios que arrancan con el sistema:** herramienta de configuración del sistema (`msconfig`), pestaña **Servicios**.
- **Servicios instalados:** **Panel de control → Herramientas de Windows → Servicios**, con nombre, descripción y estado.

Con el botón derecho sobre un servicio: **Iniciar**, **Detener**, **Pausar**, **Reanudar**, **Reiniciar**, **Actualizar** y **Propiedades**.

En **Propiedades** se consulta y cambia el **tipo de inicio**:

| Tipo de inicio | Comportamiento |
| :-: | --- |
| **Automático** | Se ejecuta al iniciar el sistema. Opción **Inicio retrasado**: cuando el SO ha terminado de iniciarse. |
| **Manual** | Se ejecuta cuando el usuario lo inicia. |
| **Deshabilitado** | No puede iniciarse hasta cambiar el tipo de inicio. |

Automático y Manual pueden tener la opción **Desencadenar inicio**.

> [!note] Desencadenar inicio
> El servicio arranca (o se detiene) solo cuando ocurre un **evento desencadenante**: conexión de un dispositivo, llegada a una red, unión al dominio, cambio de directiva, petición a un puerto, etc. Así no consume recursos mientras no se necesita.

> - [Microsoft Learn – Service Trigger Events](https://learn.microsoft.com/en-us/windows/win32/services/service-trigger-events).
