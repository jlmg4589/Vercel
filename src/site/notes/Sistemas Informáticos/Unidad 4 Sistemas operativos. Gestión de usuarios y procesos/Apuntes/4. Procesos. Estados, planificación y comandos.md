# Unidad 4: Sistemas operativos. Gestión de usuarios y procesos

> [!abstract] Criterios que se trabajan
> **CE4C** (identificar, arrancar y detener procesos), **CE4E** (comandos) y **CE4F** (monitorización). Contenidos **BC4_5** y **BC4_6**.

## 4.1 Procesos y planificación

El **planificador de procesos** es el módulo del sistema operativo que gestiona los procesos: creación, comunicación, compartición y finalización.

- **Ventaja:** favorece la multitarea y evita que los procesos que necesitan mucho tiempo de CPU la acaparen.
- Establece y cambia el estado de cada proceso según un **algoritmo de planificación**, que asigna un tiempo de ejecución o **cuantum** a los procesos en ejecución.
- Pasado el cuantum se produce una **interrupción de reloj**: el SO recupera el control y el planificador toma el siguiente proceso de la cola de listos según su algoritmo (prioridades).

> [!note]
> Conviene conocer la política de planificación del SO, porque beneficia o perjudica a cada tipo de proceso. No existe una política óptima para todos los procesos.

### 4.1.1 Estados de un proceso

| Estado | Descripción |
| :-: | --- |
| **Nuevo** | Se crean sus estructuras de datos y se le asigna memoria. La principal es el **PCB** (bloque de control de proceso). |
| **Listo** | Preparado para ejecutarse: recién creado, desbloqueado o con el cuantum agotado. |
| **Ejecutándose** | Ocupa la CPU. El planificador elige cuál de la cola de listos pasa a ejecución. |
| **Bloqueado** | Espera un suceso (acceso a un recurso, E/S, intervención del usuario…). |
| **Finalizado** | Ha terminado: se liberan sus recursos y se elimina su PCB. |

> [!warning] Falta fuente: diagramas
> Los diagramas "Ciclo de vida de un proceso" y "Cambio de contexto" del Tema 4 son imágenes no disponibles.

El tiempo de ejecución y el estado de un proceso son **impredecibles**: no se sabe de antemano cuánto durará, si se bloqueará ni cuánto estará en la cola de listos.

Un **cambio de contexto** se produce cuando un proceso entra en ejecución y otro sale: se actualizan las estructuras de gestión del SO y los registros de la CPU con los datos del nuevo proceso. Toda la información de estado se guarda en el PCB.

### 4.1.2 Modos de ejecución del procesador

| Modo | Uso |
| --- | --- |
| **Usuario** | Programas de usuario y actividades no críticas del SO; puede haber varios niveles por privilegios o prioridades. |
| **Kernel (núcleo o privilegiado)** | Instrucciones del núcleo, con control total: crear, terminar y sincronizar procesos, gestionar memoria, interrupciones… |

> [!note]
> Si un programa en modo usuario necesita una operación crítica, debe pedírsela al SO, que la ejecuta en modo kernel. Esto depende de la arquitectura del SO (monolítica, micronúcleo o híbrida), ver [[Sistemas Informáticos/Unidad 2 Sistemas operativos. Introducción/Apuntes/4. Tipos y arquitecturas de sistemas operativos#4.2 Arquitecturas de los sistemas operativos\|UD2]].

### 4.1.3 Modos de ejecución de los procesos

- **Por lotes (*batch*):** se lanza un conjunto de tareas que se ejecutan una tras otra sin intervención del usuario (copias de seguridad automáticas, trabajos de impresión).
- **Interactivo:** requieren continuamente acciones del usuario (diseño por ordenador, hoja de cálculo, videojuego, navegador).

> [!note] Servicios o demonios
> Procesos que normalmente arrancan con el sistema y se ejecutan en **segundo plano**. Ver [[Sistemas Informáticos/Unidad 4 Sistemas operativos. Gestión de usuarios y procesos/Apuntes/5. Gestión de servicios en Linux y Windows\|5. Gestión de servicios en Linux y Windows]].

## 4.2 Identificación de procesos. El PCB

El PCB almacena, entre otros:

- **PID:** identificador único del proceso.
- **PPID:** PID del proceso padre (el que lo creó).
- Usuario propietario.
- Estado del procesador en el último cambio de contexto.
- Estado.
- Referencias de memoria RAM.
- Ficheros abiertos.
- *Buffers* de memoria utilizados.

> [!note]
> El superusuario o los usuarios con potestad de administración son los únicos que pueden gestionar todos los procesos; cada usuario puede gestionar los suyos.

## 4.3 Monitor del sistema (Linux, gráfico)

En Ubuntu, el **Monitor del sistema**, pestaña **Procesos**, muestra los procesos en ejecución. Con el botón secundario sobre uno se puede: ver sus **propiedades**, cambiar su **prioridad**, **detenerlo**, **continuarlo**, **finalizarlo** (terminar) o **matarlo** (enviar la señal de matar).

## 4.4 Comandos para gestionar procesos en Linux

### 4.4.1 ps

Informa del estado de los procesos en ejecución: `ps [modificadores]`. Cada letra de los modificadores es una acción y juntas se combinan.

| Objetivo | Comando |
| --- | --- |
| Todos los procesos | `ps aux`, `ps -ef` |
| Ordenados por tiempo de CPU | `ps aux --sort cputime` |
| Con árbol de procesos | `ps axjf` |
| De un usuario | `ps -U luis u` |
| Por PID | `ps --pid 8943` |
| De un terminal | `ps -t /dev/pts/2` |

Columnas de la cabecera:

| Columna | Significado |
| :-: | --- |
| UID | Usuario propietario. |
| PID | Identificador del proceso. |
| PPID | Identificador del padre. |
| C | Uso reciente del procesador (para calcular la prioridad). |
| STIME | Hora de inicio. |
| TTY | Terminal de lanzamiento. |
| TIME | Tiempo de CPU consumido. |
| COMMAND | Orden ejecutada. |
| VSZ | Tamaño en memoria virtual (KB). |
| RSS | Memoria residente en memoria física (KB). |
| %CPU | Porcentaje de CPU. |
| %MEM | Porcentaje de memoria. |
| STAT o S | Estado del proceso. |

> [!warning] Falta fuente: códigos de STAT
> La tabla de códigos de estado (STAT) es una imagen no disponible. En `top` la fuente cita R (ejecutándose o listo), S (bloqueado o hibernando), T (parado) y Z (zombi).

Se puede filtrar con `grep`:

```bash
ps aux | grep bash
```

### 4.4.2 pstree y top

- **`pstree`:** muestra los procesos en forma de árbol.
- **`top`:** estado del sistema y de los procesos **en tiempo real** (actualización continua, no una instantánea). Se sale con `q`.

Cabecera de `top`:

| Línea | Información |
| :-: | --- |
| 1.ª | Hora, tiempo encendido, n.º de usuarios y carga media a 1, 5 y 15 minutos. |
| 2.ª | Tareas: total, ejecutándose o listas (R), bloqueadas o hibernando (S), paradas (T) y zombis (Z). |
| 3.ª | Tiempos de CPU de usuario, del kernel, etc. |
| 4.ª | Memoria física en MB: total, libre, usada y en *buffer*. |
| 5.ª | Memoria virtual en MB: total, libre, usada y disponible. |

El resto muestra los procesos con columnas similares a las de `ps`. Por defecto se actualiza cada 3 segundos.

```bash
top -d 2 -u luis   # procesos de luis, actualizando cada 2 s
top -p 8933        # solo el proceso 8933
```

### 4.4.3 Primer y segundo plano

- **Primer plano (*foreground*):** el shell crea un subshell que ejecuta el comando; el usuario espera a que termine para recuperar el prompt.
- **Segundo plano (*background*):** se añade `&` al final; el prompt vuelve de inmediato. Se muestra el número de tarea (entre corchetes) y el PID.

```bash
yes > /dev/null      # primer plano: se mata con CTRL+C
yes > /dev/null &    # segundo plano
```

`yes` imprime "y" indefinidamente; se redirige a `/dev/null` (la "cubeta de bits") para no llenar la pantalla.

| Comando | Función |
| --- | --- |
| `jobs` | Lista las tareas en segundo plano (`+` la más reciente, `-` la anterior). |
| `fg [%][tarea]` | Pasa una tarea a primer plano (sin argumentos, la más reciente). |
| `bg [%][tarea]` | Pasa una tarea a segundo plano. Antes hay que detenerla con **CTRL+Z**. |
| `sleep 12` | Bloquea la ejecución el tiempo indicado (en segundos por defecto). |

### 4.4.4 Prioridad. nice y renice

El algoritmo de planificación combina **Round Robin**, **FIFO**, prioridades… La prioridad real se calcula con varios factores y se puede alterar relativamente con el valor **nice**:

- Va de **-20** (máxima prioridad) a **19** (mínima).
- Por defecto un proceso se lanza con nice **0**.
- Lo puede cambiar el propietario o el superusuario; un usuario común **solo puede disminuir** la prioridad ("ser amable" con el sistema).
- Se comprueba con `ps -l`, columnas **NI** y **PRI** (80 por defecto).

```text
nice -{+|-}[prioridad] comando
renice -{+|-}[prioridad] [[-p] PID...] [[-u] usuarios]
```

`nice` lanza un proceso con otra prioridad; `renice` la cambia cuando ya está en marcha.

### 4.4.5 Envío de señales. kill

Los procesos reciben señales del propio SO y del exterior. `kill` permite enviarlas:

```bash
kill -señal PID
```

| N.º | Señal | Efecto |
| :-: | :-: | --- |
| 2 | SIGINT | Interrumpe (como CTRL+C). |
| 9 | SIGKILL | Mata el proceso. |
| 15 | SIGTERM | Termina; puede ignorarse, por lo que SIGKILL es más efectiva. |
| 18 | SIGCONT | Continúa un proceso detenido. |
| 19 | SIGSTOP | Pausa el proceso. |

> [!note]
> CTRL+C solo llega a procesos en primer plano; con `kill` se pueden enviar señales desde otros orígenes, como otro terminal. Se puede usar el número o el nombre de la señal.

> [!note] CTRL+Z y las señales
> CTRL+Z envía **SIGTSTP** (20), una pausa "suave" que el programa puede capturar; SIGSTOP no puede capturarse ni ignorarse. El proceso detenido se reanuda con `fg` (primer plano) o `bg` (segundo plano), que le envían SIGCONT; pulsar de nuevo CTRL+Z no lo reanuda.

> [!info] Fuentes
> - [signal(7) – man7.org](https://man7.org/linux/man-pages/man7/signal.7.html) (números y comportamiento de SIGSTOP, SIGTSTP, SIGCONT en x86/ARM).
> - [Bash Reference Manual – Job Control Basics](https://www.gnu.org/software/bash/manual/html_node/Job-Control-Basics.html).

> [!warning] Falta fuente: openSUSE
> Los comandos de procesos son comunes, pero no hay fuente sobre la herramienta gráfica de procesos de openSUSE.

## 4.5 Gestión de procesos en Windows (interfaz gráfica)

La planificación en Windows usa **colas múltiples por prioridades**, con distintos algoritmos (uno de ellos, Round-Robin).

Se gestiona con el **Administrador de tareas**:

- Pestaña **Procesos:** procesos agrupados en **Aplicaciones**, **Procesos en segundo plano** y **Procesos de Windows**. Con el botón derecho se ven detalles o se **finaliza** la tarea, entre otras opciones.
- Pestaña **Detalles:** información pormenorizada y más opciones, como **establecer la prioridad** o la **afinidad** con la CPU.

> [!warning] Falta fuente: comandos de Windows
> No hay fuente sobre comandos de procesos en Windows (`tasklist`, `taskkill`, `Get-Process`, `Stop-Process`).
