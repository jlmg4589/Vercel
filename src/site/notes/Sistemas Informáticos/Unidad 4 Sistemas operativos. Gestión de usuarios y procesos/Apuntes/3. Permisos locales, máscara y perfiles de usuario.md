# Unidad 4: Sistemas operativos. Gestión de usuarios y procesos

> [!abstract] Criterios que se trabajan
> **CE4D** (permisos locales y listas de control de acceso) y **CE4E** (comandos de administración). Contenidos **BC4_4** y **BC4_6**.

## 3.1 Acceso a recursos y permisos locales en Linux

Los archivos son recursos del sistema operativo, que debe poder discriminar qué usuarios y grupos acceden a ellos y con qué operaciones. El **i-nodo** de cada archivo guarda el **propietario (UID)**, el **grupo propietario (GID)** y la **máscara de permisos**, con tres grupos de tres bits:

| Grupo de bits | Destinatario |
| :-: | --- |
| 1.º (usuario) | El propietario del archivo. |
| 2.º (grupo) | Usuarios que pertenecen al grupo del fichero. |
| 3.º (otros) | Quien no es propietario ni pertenece al grupo. |

Cada grupo tiene permisos de **lectura (r)**, **escritura (w)** y **ejecución (x)**, visibles con `ls -l`. La ausencia de permiso se representa con `-`. Los permisos se interpretan de forma distinta en ficheros y en directorios.

> [!warning] Falta fuente: tabla de significado en ficheros y directorios
> La tabla del Tema 4 que explica r, w, x en ficheros y directorios y los ejemplos de máscaras son imágenes no disponibles en el texto extraído.

> [!note] Más allá de propietario, grupo y otros
> Los permisos solo se asocian al propietario, al grupo y al resto. Para dar permisos a otro conjunto de usuarios hacen falta las **listas de control de acceso (ACL)**, con `getfacl` (obtener) y `setfacl` (establecer). Las ACL se desarrollan en la [[Sistemas Informáticos/Unidad 6 Gestión de recursos en red de un sistema informático/Apuntes/1. Permisos, herencia y listas de control de acceso#1.5 Listas de control de acceso (ACL)\|UD6 · Listas de control de acceso (ACL)]] (BC6_1).

Para cambiar el propietario o el grupo de un archivo, ver [[Sistemas Informáticos/Unidad 4 Sistemas operativos. Gestión de usuarios y procesos/Apuntes/1. Usuarios y grupos locales en Linux y Windows#1.2.3 Propietario y grupo de archivos\|chown y chgrp]].

## 3.2 Bits especiales

| Bit | En archivos | En directorios | Símbolo | Posición |
| --- | --- | --- | :-: | --- |
| **Set-uid** | Al ejecutarlo otro usuario, toma el UID del propietario (si es root, se ejecuta como root) solo durante la ejecución. | Sin efecto. | `s` / `S` | Ejecución del propietario |
| **Set-gid** | Se ejecuta con el GID del grupo del fichero. | Lo creado dentro hereda el grupo del directorio, no el del creador. | `s` / `S` | Ejecución del grupo |
| **Sticky-bit** | Sin efecto actualmente en Linux. | Solo el propietario de cada archivo (o del directorio) puede borrarlo o modificarlo, aunque otros tengan rwx. | `t` / `T` | Ejecución de otros |

- La letra **minúscula** indica que el bit está activo y hay permiso de ejecución; la **mayúscula**, que no hay permiso de ejecución (y entonces no tiene efecto).
- Set-uid **solo es aplicable a binarios**, no a scripts de bash o sh.

> [!example] Ejemplos
> - `passwd` tiene set-uid: cualquier usuario lo ejecuta como root para modificar `/etc/passwd` y `/etc/shadow` al cambiar su contraseña. Lo mismo ocurre con `su`.
> - `/tmp` y `/var/tmp` tienen sticky-bit: todos pueden crear archivos, pero solo su creador puede borrarlos o modificarlos.

## 3.3 Modificación de permisos. chmod

`chmod` (*change mode*) cambia los permisos; lo puede usar el propietario o el superusuario.

```bash
chmod [opciones] permisos archivos
```

`-R`: recursivo en directorios. Los permisos se indican en modo **numérico** o **simbólico**.

### 3.3.1 Modo numérico (octal)

Cada bit se activa con 1 o se desactiva con 0, y el binario se pasa a octal:

| Máscara | `rwx` | `rw-` | `r--` |
| --- | :-: | :-: | :-: |
| Binario | 111 | 110 | 100 |
| Octal | 7 | 6 | 4 |

Así, `rwxrw-r--` = `111110100` = **764**.

Bits especiales: se suman al valor anterior.

| Bit | Suma en octal |
| --- | :-: |
| Sticky-bit | 1000 |
| Set-gid | 2000 |
| Set-uid | 4000 |

```bash
chmod 5764 prueba.txt    # rwsrw-r-T
```

### 3.3.2 Modo simbólico

Más sencillo, sobre todo para modificar respecto al valor actual. Se pueden encadenar varios modos separados por comas.

```text
chmod [u][g][o][a]{+|=|-}[r][w][x][s][t] archivos
```

| Destinatario | | Operación | | Permiso | |
| :-: | --- | :-: | --- | :-: | --- |
| `u` | propietario | `+` | añade | `r` | lectura |
| `g` | grupo | `=` | establece y anula el resto | `w` | escritura |
| `o` | otros | `-` | quita | `x` | ejecución |
| `a` | todos | | | `s` | set-uid / set-gid (según u o g) |
| | | | | `t` | sticky-bit |

```bash
chmod go-r prueba.txt    # quita la lectura a grupo y otros
```

> [!tip] Proyecto Game Over
> Para ejecutar los scripts de Bash del [[Sistemas Informáticos/00_General/Proyecto anual Game Over\|Proyecto anual Game Over]] hay que darles permiso de ejecución, por ejemplo con `chmod u+x saludo.sh`.

## 3.4 Permisos por defecto. umask

Los permisos originales son **0666** para archivos y **0777** para directorios. Al crearlos se les aplica una máscara (*umask*), por defecto **0022** o **0002** según la distribución.

```bash
umask [máscara]
```

Sin argumento muestra la máscara actual; la máscara se da en octal (con `-S` se usa notación simbólica).

Cálculo de los permisos resultantes:

1. Pasar la máscara original (*mask*) y la *umask* de octal a binario.
2. Aplicar **NOT** a la umask.
3. Hacer **AND** entre los permisos originales y la umask negada.

> [!example] umask 022 (cálculo a partir del procedimiento de la fuente)
> - Archivo: $666 \text{ AND NOT } 022$ → `110 110 110` AND `111 101 101` = `110 100 100` = **644** (`rw-r--r--`).
> - Directorio: $777 \text{ AND NOT } 022$ → `111 101 101` = **755** (`rwxr-xr-x`).

> [!note]
> Los archivos nunca obtienen permiso de ejecución por la umask, porque sus permisos originales (0666) no lo tienen.

El cambio con `umask` es **temporal**: solo afecta al shell y a sus procesos hijos. Para hacerlo permanente:

- **Global:** `/etc/profile` (todos los usuarios; requiere superusuario).
- **Local:** `~/.bashrc` (solo esa cuenta).

## 3.5 Configuración de perfiles

Los **perfiles de usuario** guardan la configuración del entorno de trabajo, desde que el usuario inicia sesión hasta que se desconecta:

- **Archivos globales:** afectan a todos; requieren superusuario.
- **Archivos locales:** en el home de cada usuario; solo le afectan y puede editarlos.

Se editan para asignar o personalizar variables, ejecutar comandos al entrar o salir del sistema o del intérprete, asignar el `PATH` (rutas de búsqueda de ejecutables) y personalizar el *prompt*. El shell se configura mediante **variables** y **alias**.

### 3.5.1 Variables

Una variable es un identificador que almacena una cadena; la usan el sistema, los programas y el propio shell.

```bash
VARIABLE=VALOR
VARIABLE=valor1:valor2:...
VARIABLE="valor con espacios"
echo $VARIABLE
```

| Tipo | Descripción | Listar |
| --- | --- | --- |
| **Globales o de entorno** | Las reconocen los procesos hijos del shell. | `env`, `printenv` |
| **Locales o de shell** | Solo las interpreta el shell donde se definen. | `set` (muestra también las de entorno) |

| Acción | Comando |
| --- | --- |
| Hacer global una variable | `export VARIABLE` |
| Pasar de global a local | `export -n VARIABLE` |
| Eliminarla | `unset VARIABLE` |

Al cerrar el terminal, las variables desaparecen. Para hacerlas permanentes se definen en un archivo de perfil, normalmente `~/.bashrc`, precedidas de `export` si se quieren globales.

### 3.5.2 Alias

Permiten ejecutar comandos de forma personalizada y ahorrar escritura. Actúan como variables locales: desaparecen al terminar el shell salvo que se definan en `~/.bashrc`.

```bash
alias                          # lista los alias
alias nombre_alias="comandos"  # crea un alias
unalias nombre_alias           # lo elimina
```

## 3.6 Permisos locales en Windows

En las **Propiedades** de un elemento → pestaña **Seguridad** → **Editar...** se modifican los permisos; con **Agregar...** se añade un usuario o grupo y se le conceden o deniegan permisos.

Los permisos se pueden **permitir** o **denegar** a usuarios y grupos; en caso de conflicto **prevalece la denegación**.

| Permiso | Efecto |
| --- | --- |
| **Control total** | Todos los permisos. |
| **Modificar** | Leer, escribir, ejecutar y **eliminar**; no permite cambiar permisos ni tomar posesión (eso solo lo da Control total). |
| **Lectura y ejecución** | Leer un archivo y ejecutar programas o scripts; en carpetas, ver el contenido y ejecutar sus archivos. |
| **Mostrar contenido de carpeta** | Solo carpetas: ver el contenido sin leer ni ejecutar los archivos. |
| **Lectura** | Leer archivos sin ejecutarlos; en carpetas, ver el contenido. |
| **Escritura** | Crear elementos o cambiar el contenido. |
