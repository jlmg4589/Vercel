# Unidad 4: Sistemas operativos. Gestión de usuarios y procesos

> [!abstract] Criterios que se trabajan
> **CE4A** (cuentas de usuario locales y grupos) y **CE4E** (comandos de configuración y administración). Contenidos **BC4_1** y **BC4_6**.

En esta unidad se trabaja la gestión de usuarios y de procesos en **Ubuntu** y **Microsoft Windows**, tanto por línea de comandos (conociendo su sintaxis) como con herramientas gráficas.

## 1.1 Usuarios y grupos en Linux

Los sistemas GNU/Linux gestionan los usuarios mediante **archivos de configuración**. Los usuarios comunes no tienen privilegios sobre ellos: solo los administradores o **root** pueden editarlos. A veces la edición puede ser directa, pero en otros casos es recomendable emplear comandos concretos para evitar errores de sintaxis o de formato.

Los usuarios y grupos se gestionan principalmente con `/etc/passwd` y `/etc/group`, además de otros ficheros como `/etc/sudoers` o `/etc/shadow`.

Linux es **multiusuario**: puede haber varios usuarios trabajando a la vez. Cada usuario debe pertenecer a un grupo y puede pertenecer a varios.

### 1.1.1 Gestión en el entorno gráfico (Ubuntu)

1. **Configuración → Usuarios**.
2. **Desbloquear** (para editar un usuario o agregar nuevos).
3. **Añadir usuario**, indicando:
   - **Tipo de cuenta:** estándar o administrador.
   - **Nombre completo:** nombre de pila del usuario.
   - **Nombre de usuario** (*login*).
   - **Contraseña:** establecerla ahora o dejar que la ponga el usuario al iniciar sesión.

Para una gestión más completa se instala la aplicación **Usuarios y grupos**:

```bash
sudo apt install gnome-system-tools
```

Desde la ventana **Ajustes de los usuarios** se puede:

- Añadir o eliminar usuarios.
- **Gestionar grupos:** añadir, eliminar y, en **Propiedades**, modificar el GID o los miembros.
- **Ajustes avanzados:**
  - **Información del contacto** (oficina, teléfonos…).
  - **Privilegios del usuario** (acceso a recursos).
  - Pestaña **Avanzado**: desactivar la cuenta (añade `!` al inicio del campo de contraseña en `/etc/shadow`), cambiar el directorio personal, la shell, el grupo principal y el UID.

> [!warning] Falta fuente: openSUSE
> No hay fuente sobre la gestión gráfica de usuarios en openSUSE (YaST).

### 1.1.2 Ficheros de configuración

#### /etc/passwd

Almacena las cuentas de usuario. Una fila por usuario, con **siete campos** separados por `:`:

| N.º | Campo | Descripción |
| :-: | --- | --- |
| 1 | Login | Nombre para acceder al sistema. |
| 2 | Password | Aparece una `x`: la contraseña está cifrada en `/etc/shadow`. |
| 3 | UID | Identificador único de usuario. 0 = superusuario; 1-99 cuentas predeterminadas; 100-999 cuentas administrativas del sistema; los nuevos usuarios, desde 1000. |
| 4 | GID | Identificador del **grupo principal**. |
| 5 | Información personal | Teléfono, oficina… |
| 6 | Home | Directorio de trabajo inicial. |
| 7 | Shell | Intérprete de comandos al iniciar sesión. |

```text
login:x:UID:GID:información:home:shell
```

El **administrador** en Linux es quien tiene capacidad de gestión, sin ser necesariamente root: puede tenerla con `sudo` o por pertenecer a grupos con privilegios sobre ciertos archivos o comandos. Los **grupos** facilitan la administración de privilegios, por ejemplo para dar a varios usuarios permisos sobre archivos que no son suyos.

#### /etc/group

Centraliza los grupos. Una fila por grupo, con **cuatro campos** separados por `:`:

| N.º | Campo | Descripción |
| :-: | --- | --- |
| 1 | Nombre del grupo | Asociado al GID. |
| 2 | Contraseña | No se suele usar; `x` indica que está en `/etc/gshadow`. |
| 3 | GID | Identificador único del grupo. |
| 4 | Lista de usuarios | Usuarios que lo tienen como **grupo secundario**. |

> [!note]
> Cada usuario tiene un **grupo principal** (cuarto campo de `/etc/passwd`) y puede tener varios **grupos secundarios**.

Al dar de alta un usuario se le asocia un grupo con su mismo nombre. Grupos que Linux crea por defecto según la fuente:

| Grupo | Uso |
| :-: | --- |
| `users` | Grupo general de usuarios. |
| `ssh` | Usuarios con conexión remota por SSH. |
| `dhcp` | Administran el servicio DHCP. |
| `root` | Usuario root y quienes administran casi por completo el equipo. Para usar privilegios root la clave es la contraseña de inicio de sesión del usuario inicial. |
| `admin` | Privilegios de administración (por ejemplo, el usuario creado en la instalación). |

> [!note] Grupos por defecto según la distribución
> La lista anterior depende de la distribución y de los paquetes instalados. En Ubuntu, desde la versión 12.04, el grupo administrativo es **`sudo`** (el antiguo `admin` solo se conserva por compatibilidad), y no existen por defecto grupos `ssh` ni `dhcp`. Además, `root` se usa normalmente sin contraseña propia: se obtienen sus privilegios con `sudo` y la contraseña del propio usuario. Se pueden consultar los grupos reales con `getent group` o `cat /etc/group`.

#### Otros ficheros

| Fichero | Contenido |
| --- | --- |
| `/etc/login.defs` | Valores predeterminados de un usuario nuevo ("plantilla"): `ENCRYPT_METHOD SHA512`, `UMASK 022`, `HOME_MODE 0750`, `LOGIN_RETRIES 5`… |
| `/etc/shadow` | Contraseñas cifradas e información de caducidad; solo accesible por root/administradores. Ver [[Sistemas Informáticos/Unidad 4 Sistemas operativos. Gestión de usuarios y procesos/Apuntes/2. Seguridad de cuentas de usuario y contraseñas#2.2 El fichero /etc/shadow\|/etc/shadow]]. |
| `/etc/gshadow` | Contraseñas de los grupos. Se usa cuando un no miembro quiere unirse con `newgrp`; si la contraseña empieza por `!`, nadie puede acceder con `newgrp`. Solo root puede leerlo. Formato: `nombre:contraseña:administradores:miembros`. |
| `/etc/deluser.conf` | Parámetros predeterminados de `deluser` y `delgroup`. |
| `/etc/adduser.conf` | Parámetros de `adduser` y `addgroup`: `DSHELL=/bin/bash`, `DHOME=/home`, `SKEL=/etc/skel`, rangos de UID y GID… |
| `/etc/shells` | Rutas de las shells válidas. |
| `/etc/skel` | Contenido que se copia en la carpeta personal de cada usuario nuevo (junto con Descargas, Documentos, Escritorio, Imágenes, Música). Los directorios predeterminados se configuran en `/etc/xdg/user-dirs.defaults`. |

Shells habituales en `/etc/shells`:

| Shell | Descripción |
| --- | --- |
| `/bin/sh` | *Bourne Shell*, la disponible desde los inicios. |
| `/bin/bash` | *Bourne-Again Shell*, la de por defecto; reemplazo de la anterior. |
| `/bin/rbash` | *Restricted bash*: sin cambiar de directorio, redirecciones, variables de entorno, etc. |
| `/bin/dash` | *Debian Almquist Shell*: compatible con sh, más pequeña y rápida que bash. |

Un usuario sin shell válida, o con `/bin/false` o `/usr/sbin/nologin`, **no puede iniciar sesión**.

```bash
sudo nano /etc/xdg/user-dirs.defaults
```

### 1.1.3 Cambiar de usuario o ejecutar comandos con privilegios

Se puede entrar como root, pero es más recomendable usar `sudo`.

| Comando | Función | Opciones |
| --- | --- | --- |
| `su [opciones] [login]` | Cambia temporalmente de identidad (sin login, a root). Se vuelve con `exit`. | `-l`: ejecuta los scripts de inicio de sesión y simula el entorno del usuario destino. |
| `sudo [opciones] [usuario]` | Ejecuta comandos con privilegios de root (o del usuario indicado). El usuario debe estar en `/etc/sudoers` o en el grupo `sudo`. Pide la clave del propio usuario y no la vuelve a pedir durante un tiempo. | `-l`: sin comando, muestra qué puede hacer el usuario. `-u`: actúa como el usuario indicado. |
| `visudo` | Editor de `/etc/sudoers` (la primera vez pregunta el editor; recomienda nano). | |

Líneas típicas de `/etc/sudoers`:

```text
root    ALL=(ALL:ALL) ALL
%sudo   ALL=(ALL:ALL) ALL
```

- `root`: puede ejecutar cualquier comando, como cualquier usuario y grupo, desde cualquier equipo.
- `%sudo`: los miembros del grupo `sudo` tienen todos los privilegios de root al usar `sudo` (el `%` indica grupo).

Formato general:

```text
usuario hosts=(usuarios:grupos) comandos
%grupo  hosts=(usuarios:grupos) comandos
```

Cada campo admite una lista separada por comas o `ALL`. Los hosts se identifican por IP o por nombre del equipo.

## 1.2 Comandos de gestión de usuarios y grupos en Linux

La mayoría requiere permisos de administrador (root o `sudo`). `adduser`, `addgroup`, `deluser` y `delgroup` dependen de la distribución: son **scripts** sobre `useradd`, `groupadd`, `userdel` y `groupdel` con algún añadido.

### 1.2.1 Usuarios

**`useradd [opciones] login`**: crea la cuenta según los valores por defecto y las opciones. Después hay que darle contraseña con `passwd`.

| Opción | Significado |
| :-: | --- |
| `-c "comentario"` | Información del usuario. |
| `-d directorio -m` | Directorio home; `-m` fuerza su creación si no existe. |
| `-s shell` | Shell por defecto. |
| `-g grupo` | Grupo primario. |
| `-G g1,g2,...` | Grupos secundarios (separados por comas, sin espacios). |
| `-p contraseña` | Contraseña (debe ir cifrada; se usa junto con `openssl`, ver [[Sistemas Informáticos/Unidad 4 Sistemas operativos. Gestión de usuarios y procesos/Apuntes/2. Seguridad de cuentas de usuario y contraseñas#2.3 Asignar contraseñas cifradas. openssl passwd\|openssl passwd]]). Sin ella, el usuario no puede acceder. |

```bash
useradd -c "usuario nuevo" -d /home/user1 -m -g Grupo1 -G Grupo2,Grupo3 Usuario1
```

**`usermod [opciones] login`**: modifica una cuenta existente. Tiene las mismas opciones que `useradd`, además de:

| Opción | Significado |
| :-: | --- |
| `-a` | Añade a los grupos indicados con `-G` (sin quitar los actuales). |
| `-d directorio` | Nuevo home. |
| `-m` | Mueve el contenido del antiguo home al indicado con `-d` (el antiguo desaparece; el nuevo no debe existir). |
| `-l nuevoLogin` | Cambia el login. |
| `-L` | Bloquea la cuenta (añade `!` en `/etc/shadow`). |
| `-U` | Desbloquea la cuenta. |

```bash
usermod -c "usuario nuevo" -d /home/usr1 -m -g Grupo2 -aG Grupo3 -l Usr1 Usuario1
```

| Comando | Sintaxis | Función |
| --- | --- | --- |
| `adduser` | `adduser login grupo` / `adduser login` | Añade un usuario a un grupo, o crea un usuario haciendo preguntas (no todas obligatorias). |
| `deluser` | `deluser login grupo` / `deluser login` | Quita un usuario de un grupo, o elimina el usuario. `--remove-home` borra su home; `--remove-all-files` borra todos sus ficheros. |
| `userdel` | `userdel [opciones] login` | Elimina la cuenta. `-r` borra el home. |
| `passwd` | `passwd [opciones] login` | Gestiona la contraseña (ver [[Sistemas Informáticos/Unidad 4 Sistemas operativos. Gestión de usuarios y procesos/Apuntes/2. Seguridad de cuentas de usuario y contraseñas\|2. Seguridad de cuentas de usuario y contraseñas]]). |
| `id` | `id [login]` | Muestra UID, GID principal y GID secundarios (sin login, el usuario actual). |
| `groups` | `groups [user]` | Lista los grupos: el primero es el principal y los demás, secundarios. |

### 1.2.2 Grupos

| Comando | Sintaxis | Función |
| --- | --- | --- |
| `groupadd` | `groupadd [opciones] grupo` | Crea un grupo vacío. `-g GID` asigna el GID (≥ 1000, sin repetir). Da error si el grupo o el GID ya existen. |
| `addgroup` | `addgroup grupo` / `addgroup login grupo` | Añade un grupo o agrega un usuario a un grupo. |
| `groupmod` | `groupmod [opciones] grupo` | `-g` cambia el GID; `-n` cambia el nombre. |
| `groupdel` | `groupdel grupo` | Elimina un grupo. **No** permite borrar el grupo principal de un usuario existente: antes hay que eliminar el usuario o cambiarle el grupo principal. |
| `delgroup` | `delgroup [opciones] grupo` / `delgroup login grupo` | Elimina un grupo o quita un usuario de él. `--only-if-empty`: solo si no tiene usuarios. |
| `gpasswd` | `gpasswd [opciones] [login] grupo` | Gestiona pertenencia y configuración de grupos. Quitar un usuario: `sudo gpasswd -d <login> <grupo>`. |

> [!info] Fuentes
> - [groupdel(8) – man7.org](https://man7.org/linux/man-pages/man8/groupdel.8.html): "You may not remove the primary group of any existing user."
> - [Ubuntu Server docs – User management](https://documentation.ubuntu.com/server/how-to/security/user-management/) y [Ubuntu Wiki – RootSudo](https://help.ubuntu.com/community/RootSudo) (grupo `sudo`, cuenta root bloqueada).

### 1.2.3 Propietario y grupo de archivos

**`chown [opciones] [nuevo_propietario][:][nuevo_grupo] fichero...`** (*change owner*): cambia propietario y/o grupo. Ambos deben existir.

- `-R`: recursivo.
- `-h`: afecta al enlace simbólico y no al archivo referenciado.
- El separador es `.` o `:` según la distribución.

> [!example] Restricciones de chown
> El usuario `luis` no puede asignar la propiedad de `propietario.txt` a `maria`, pero sí cambiar el grupo (porque `luis` pertenece al grupo de `maria`). Con `sudo` no hay esa limitación.

**`chgrp [opciones] nuevo_grupo fichero...`**: cambia el grupo de uno o varios ficheros o directorios. `-R`: recursivo.

> [!warning] Falta fuente: openSUSE
> En openSUSE `adduser`/`addgroup` no se comportan como en Ubuntu y existen herramientas propias (YaST). No hay fuente sobre ello.

## 1.3 Usuarios y grupos en Windows (interfaz gráfica)

### 1.3.1 Configuración → Cuentas

- **Agregar otra persona a este equipo** → solicita la forma de iniciar sesión.
- **No tengo los datos de inicio de sesión de esta persona** → pide datos para crear una cuenta nueva.
- **Agregar un usuario sin cuenta Microsoft** → usuario y contraseña tradicionales (cuenta local).

Gestión de cuentas existentes:

- **Opción 1:** desde **Cuentas**, ver los usuarios, cambiar el tipo (administrador o estándar) o eliminarlos.
- **Opción 2:** **Panel de control → Cuentas de usuario** o **Administrar otra cuenta**.

### 1.3.2 Usuarios y grupos locales

Para una administración más profunda: **Panel de control → Herramientas administrativas → Administración de equipos → Usuarios y grupos locales**. Desde aquí se gestionan todos los usuarios y grupos, se ven los miembros de cada grupo y se crean grupos nuevos.

Cuentas que Windows crea por defecto, **deshabilitadas por seguridad**:

| Cuenta | Descripción |
| :-: | --- |
| **Administrador** | Privilegios más altos; cualquier acción (similar a root en Linux). |
| **Invitado** | Acceso esporádico, apenas sin privilegios. |

> [!note]
> Los usuarios **administradores** pertenecen al grupo **Administradores** y acceden a la mayoría de configuraciones. Los **estándar** pertenecen al grupo **Usuarios** y no pueden realizar acciones que afecten a otros usuarios.

> El Tema 4 solo trata la gestión gráfica en Windows. No hay fuente sobre comandos de Windows para usuarios y grupos (`net user`, `net localgroup`, cmdlets de PowerShell).
