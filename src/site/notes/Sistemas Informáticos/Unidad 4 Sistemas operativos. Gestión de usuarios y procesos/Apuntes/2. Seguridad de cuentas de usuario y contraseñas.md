# Unidad 4: Sistemas operativos. Gestión de usuarios y procesos

> [!abstract] Criterios que se trabajan
> **CE4B** (directivas de cuenta y de contraseñas) y **CE4E** (comandos de administración). Contenidos **BC4_2** y **BC4_3**.

## 2.1 Linux-PAM

Linux emplea un sistema centralizado de autenticación para las aplicaciones o comandos que intentan acceder al sistema: **Linux-PAM**. Permite administrar la seguridad de forma versátil para cada aplicación o servicio, por ejemplo:

| Fichero | Configura |
| --- | --- |
| `/etc/pam.d/sshd` | Autenticación del servicio SSH. |
| `/etc/pam.d/sudo` | Autenticación del comando `sudo`. |
| `/etc/pam.d/cron` | Autenticación y autorización de las tareas programadas (cron). |

Linux-PAM usa el fichero `/etc/shadow`.

## 2.2 El fichero /etc/shadow

Contiene las contraseñas cifradas y su política de caducidad. Una fila por usuario, con **nueve campos** separados por `:` (el noveno está reservado):

| N.º | Campo |
| :-: | --- |
| 1 | Login. |
| 2 | Contraseña cifrada. El prefijo indica el algoritmo: `$1$` (MD5), `$5$` (SHA-256), `$6$` (SHA-512). Si empieza por `!`, está **bloqueada**. |
| 3 | Días desde el 1/1/1970 hasta el último cambio de contraseña. |
| 4 | Días mínimos antes de poder cambiar la contraseña. |
| 5 | Días máximos de validez de la contraseña. |
| 6 | Días de aviso antes de que caduque. |
| 7 | Días tras la caducidad hasta deshabilitar la cuenta. |
| 8 | Días desde el 1/1/1970 en que la cuenta se deshabilitará. |
| 9 | Campo reservado para uso futuro (vacío). |

Un usuario creado con `useradd` **no tiene contraseña** y no puede acceder: un administrador (root o con `sudo`) debe asignársela.

## 2.3 Asignar contraseñas cifradas. openssl passwd

`openssl passwd` es una herramienta criptográfica que genera contraseñas *hash*.

```bash
openssl passwd [opciones] contraseña_a_encriptar
```

| Opción | Algoritmo |
| :-: | --- |
| `-1` | MD5 (inseguro actualmente). |
| `-5` | SHA-256. |
| `-6` | SHA-512. |

`useradd` y `usermod` pueden fijar la contraseña con `-p`, pero debe ir **ya cifrada**. Se puede copiar la salida de `openssl passwd` o, mejor, usar la **sustitución de comandos** `$(comando)`, que resuelve primero el paréntesis:

```bash
sudo useradd -m -p $(openssl passwd -1 oso12) carla
```

> [!warning] Seguridad de `-p`
> `useradd -p` guarda en `/etc/shadow` **exactamente** lo que recibe: si se le pasa la contraseña en claro, el usuario no podrá entrar con ella. Además, el valor queda visible en la lista de procesos y en el historial de la shell, por lo que en la práctica se prefiere `passwd` o `chpasswd`.

## 2.4 Directivas de contraseña y de cuenta en Linux

### 2.4.1 passwd

`passwd [opciones] login`. Sin parámetros, pide la contraseña antigua y dos veces la nueva del usuario actual.

| Opción | Significado |
| :-: | --- |
| `-l` | Bloquea la contraseña. |
| `-u` | Desbloquea la contraseña. |
| `-w` | Días de aviso previo a la caducidad. |
| `-x` | Días hasta que caduca. |
| `-n` | Días mínimos antes de poder cambiarla. |
| `-d` | Deja la contraseña en blanco. |
| `-e` | Expira la contraseña (cambia la fecha del último cambio). |
| `-i` | Caduca la cuenta tras X días de inactividad desde la caducidad de la contraseña. |
| `--status` | Estado de la contraseña. |

```bash
sudo passwd Paco -w 3 -x 45 -n 3
```

> [!note] Quién puede usar passwd
> Cualquier usuario puede cambiar **su propia** contraseña con `passwd` (el ejecutable tiene el bit set-uid, ver [[Sistemas Informáticos/Unidad 4 Sistemas operativos. Gestión de usuarios y procesos/Apuntes/3. Permisos locales, máscara y perfiles de usuario#3.2 Bits especiales\|bits especiales]]). Solo root puede cambiar la contraseña de **otros** usuarios y usar las opciones de bloqueo, caducidad, etc. (`-l`, `-u`, `-d`, `-e`, `-n`, `-x`, `-w`, `-i`).

> [!info] Fuentes
> - [shadow(5) – man7.org](https://man7.org/linux/man-pages/man5/shadow.5.html) (nueve campos; el último, "reserved field").
> - [useradd(8) – man7.org](https://man7.org/linux/man-pages/man8/useradd.8.html) (`-p`: "The encrypted password, as returned by crypt(3)"; no recomendado porque es visible para otros usuarios).
> - [passwd(1) – man7.org](https://man7.org/linux/man-pages/man1/passwd.1.html) (un usuario normal solo puede cambiar su propia contraseña).

### 2.4.2 chage

Gestiona la caducidad de contraseñas modificando `/etc/shadow`.

```bash
chage [opciones] [login]
```

| Opción | Significado |
| --- | --- |
| `-d`, `--lastday FECHA/DÍAS` | Fecha (o días desde 1/1/1970) del último cambio. **0** obliga a cambiar la contraseña. |
| `-E`, `--expiredate FECHA` | Fecha de caducidad de la **cuenta**. `-1` sin límite; `1` deshabilita de inmediato. |
| `-I`, `--inactive DÍAS` | Días de inactividad tras expirar la contraseña antes de bloquear la cuenta (para desbloquearla hay que acudir a un administrador). `-1` sin límite; `0` bloquea al expirar. |
| `-l`, `--list` | Muestra la información de caducidad. |
| `-m`, `--mindays DÍAS` | Días mínimos para poder cambiarla. `0` sin límite. |
| `-M`, `--maxdays DÍAS` | Días máximos de validez; después el sistema obliga a cambiarla. `-1` sin límite. |
| `-W`, `--warndays DÍAS` | Días de aviso previo. |

Modo interactivo, cómodo para configurar todos los valores:

```bash
sudo chage login
```

### 2.4.3 usermod

| Opción | Significado |
| --- | --- |
| `-e`, `--expiredate FECHA` | Caducidad de la cuenta. `-1` sin límite; `1` deshabilita de inmediato. |
| `-f`, `--inactive DÍAS` | Días tras expirar la contraseña antes de deshabilitar la cuenta. `-1` sin límite; `0` al expirar. |
| `-L`, `--lock` | Bloquea la contraseña. |
| `-U`, `--unlock` | Desbloquea la contraseña. |
| `-p`, `--password CIFRADA` | Asigna una contraseña ya cifrada. |

> [!tip] Bloquear la contraseña no deshabilita la cuenta
> Bloquear o dejar en blanco la contraseña **no** deshabilita la cuenta: el usuario podría entrar por otros medios, como **ssh**. Para deshabilitarla hay que usar `chage` o `usermod` con `--expiredate 1`. Para comprobar el estado:
> ```bash
> chage -l usuario
> passwd --status usuario
> ```
