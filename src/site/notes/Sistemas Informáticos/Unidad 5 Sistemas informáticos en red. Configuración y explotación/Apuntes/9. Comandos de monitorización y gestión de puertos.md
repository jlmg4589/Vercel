# Unidad 5: Sistemas informáticos en red. Configuración y explotación

> [!abstract] Criterios que se trabajan
> **CE5G** (verificación de la red con comandos y herramientas básicas), **CE5F** (gestión de puertos) y **CE5A**. Contenidos **BC5_3**, **BC5_5**, **BC5_6** y **BC5_8**.

## 9.1 Comando ip (GNU-Linux)

Principal comando para **mostrar información y configurar** el entorno de red de un host en GNU/Linux. Es muy potente: se recomienda consultar `man ip`.

| Acción | Comando |
| --- | --- |
| Listar las interfaces activas e inactivas | `ip a` |
| Deshabilitar una interfaz | `ip link set <interfaz> down` |
| Habilitar una interfaz | `ip link set <interfaz> up` |
| Configurar una interfaz (añadir IP) | `ip addr add <dir_IP/mascara> dev <interfaz>` |
| Eliminar la configuración (IP) de una interfaz | `ip addr del <dir_IP/mascara> dev <interfaz>` |
| Mostrar la tabla de enrutamiento | `ip route show` |
| Borrar la puerta de enlace predeterminada | `ip route del 0.0.0.0/0 via <dir_IP> dev <interfaz>` |
| Añadir una puerta de enlace predeterminada | `ip route add 0.0.0.0/0 via <dir_IP> dev <interfaz>` |
| Mostrar la tabla ARP | `ip neighbour show` |

> [!example] Configuración de una interfaz con `ip`
> ```bash
> sudo ip link set enp0s3 down
> sudo ip addr add 192.168.0.10/24 dev enp0s3
> sudo ip link set enp0s3 up
> sudo ip route add 0.0.0.0/0 via 192.168.0.1 dev enp0s3
> ip a
> ```
> (El nombre `enp0s3` y las direcciones son ilustrativos; la captura de la fuente no se ha conservado.)

> [!note]
> `ip addr del` elimina la **dirección** asignada a la interfaz, no la interfaz (la fuente dice "eliminar una interfaz"). La palabra clave es `via`, sin tilde. `0.0.0.0/0` puede escribirse también `default`.

> [!note]
> La configuración hecha con `ip` no es permanente: se pierde al reiniciar. Para que persista se usan los ficheros de configuración ([[Sistemas Informáticos/Unidad 5 Sistemas informáticos en red. Configuración y explotación/Apuntes/3. Configuración TCP-IP del cliente y ficheros de red#3.3 Ficheros de configuración de red\|Ficheros de configuración de red]]) o NetworkManager.

## 9.2 Comandos de monitorización y verificación

### 9.2.1 Equivalencias Windows / GNU-Linux

| Función | Microsoft Windows | GNU/Linux |
| --- | --- | --- |
| Ver y monitorizar interfaces | `ipconfig` | `ifconfig` (obsoleto, sustituido por `ip`), `ip a` |
| Detalles hardware de las interfaces | — | `lshw -class network` |
| Tabla ARP (MAC ↔ IP) | `arp -a` | `ip neighbour show` |
| Comprobar conectividad | `ping` | `ping` |
| Ruta de los paquetes | `tracert` | `traceroute` |
| Tabla de enrutamiento | `netstat -r` | `ip route show` |
| Puertos, sockets y conexiones | `netstat` | `ss` |
| Análisis de puertos y red | `nmap` (descarga en nmap.org) | `nmap` (instalable por línea de comandos) |

> [!warning] Falta fuente: detalles hardware de interfaces en Windows
> La fuente no indica el equivalente en Windows de `lshw`.

### 9.2.2 lshw

Identifica y muestra multitud de detalles de las interfaces de red:

```bash
sudo lshw -class network
```

### 9.2.3 arp / ip neighbour show

Muestran las asociaciones entre **direcciones físicas (MAC)** y **direcciones IP** del segmento de red local. Se almacenan en la **tabla ARP (caché ARP)** y son necesarias para incluir las MAC en las tramas de la capa de enlace. Permiten detectar a qué equipos de la red se ha conectado un host.

```cmd
arp -a
```

```bash
ip neighbour show
```

Sintaxis en Windows: `arp [opciones]`.

### 9.2.4 ipconfig / ifconfig

Permiten monitorizar las interfaces de red. En Windows se recomienda consultar la ayuda con `ipconfig /?`; `ipconfig /all` muestra la configuración completa (MAC, DHCP, DNS…). `ifconfig` pertenece al paquete obsoleto *net-tools* y puede no estar instalado.

```cmd
ipconfig
ipconfig /all
ipconfig /?
```

```bash
ifconfig
```

### 9.2.5 ping

Disponible en Windows y Linux. Comprueba una conexión enviando **paquetes de prueba** a un destino e informa del **tiempo de respuesta** si hay conexión.

```bash
ping [opciones] destino
```

- `destino`: nombre de dominio o dirección IP.
- En Windows envía 4 paquetes por defecto; en Linux envía de forma continua hasta pulsar **Ctrl+C** (o limitar con `-c n`).

Sirve para comprobar si un adaptador funciona y si hay acceso a otros equipos de la red local o de fuera (Internet), descartando errores y localizando el problema.

### 9.2.6 traceroute / tracert

Complemento de `ping` para diagnosticar fallos de **interconexión de redes**: muestra la **ruta** que sigue un paquete desde un origen IP a un destino IP, los **routers** por los que pasa y dónde puede haber un fallo.

```bash
traceroute servidor_destino
```

```cmd
tracert servidor_destino
```

### 9.2.7 nmap

Programa de **código libre** para **análisis de puertos** y **monitorización** de redes: permite escanear la red para inventariarla y monitorizarla. En Linux se instala por línea de comandos; en Windows, descargándolo de nmap.org.

```bash
nmap [opciones] objetivos
```

Ejemplos: https://www.linuxadictos.com/nmap.html

### 9.2.8 Aplicaciones de monitorización

**Wireshark**, **Pandora FMS** y **Tcpdump** permiten tareas de comprobación, monitorización, escaneo, verificación y auditoría.

## 9.3 Gestión de puertos

### 9.3.1 Puertos físicos y lógicos

- **Puerto físico:** entrada o conector de un dispositivo de red al que se conecta un medio (p. ej., un puerto RJ-45).
- **Puerto lógico:** número asociado a la aplicación de origen o destino de una comunicación. Lo usa la **capa de transporte**: en el encabezado de cada segmento TCP o UDP se indican el **puerto de origen** (aplicación que origina la comunicación) y el **puerto de destino** (aplicación de destino en el host remoto).

### 9.3.2 Rangos de puertos lógicos

| Tipo | Rango | Uso |
| --- | :-: | --- |
| **Bien conocidos** | 0 – 1023 | Aplicaciones y servicios: HTTP (80), FTP (20 datos / 21 control), SSH (22), SMTP (25), DNS (53), HTTPS (443)… |
| **Registrados** | 1024 – 49151 | Aplicaciones de usuario específicas cuando conectan con servidores. |
| **Dinámicos, privados o efímeros** | 49152 – 65535 | Puertos de origen temporales que el SO asigna a los clientes (también los usan aplicaciones P2P). |

> [!note] Puerto de FTP
> La fuente solo cita el 20. FTP usa el **21** para la conexión de **control** (órdenes) y el **20** para **datos** en modo activo.

### 9.3.3 Ejemplo: acceso a una página web

1. El **cliente** indica en el segmento el puerto de destino bien conocido **80** (HTTP) y como puerto de origen un número **aleatorio** (efímero: por encima del 1023; IANA recomienda 49152–65535, rango que usa Windows; Linux usa 32768–60999 por defecto). Así se pueden establecer simultáneamente muchas comunicaciones con un mismo servidor HTTP.
2. El **servidor** responde con puerto de origen **80** y puerto de destino el de la aplicación y comunicación concreta del cliente.

> [!note]
> Los segmentos se encapsulan en **paquetes** de la capa de red, cuyo encabezado indica las **IP de origen y destino**.

### 9.3.4 Sockets

Un **socket** es la combinación de **dirección IP + puerto**. Una comunicación entre dos hosts queda establecida por una **pareja de sockets**.

> [!example]
> `192.168.1.55:80` → IP 192.168.1.55 y puerto 80: pertenece a un **servidor HTTP** (puerto bien conocido).

### 9.3.5 netstat / ss

Monitorizan puertos, sockets y conexiones: `netstat` en Windows y `ss` en GNU/Linux. Las opciones **no** son iguales en ambos:

| Función | `ss` (Linux) | `netstat` (Windows) |
| --- | :-: | :-: |
| Todos los sockets/conexiones y puertos en escucha | `-a` | `-a` |
| Solo sockets **en escucha** | `-l` | — (filtrar `LISTENING` en `-a`) |
| Solo **TCP** / **UDP** | `-t` / `-u` | `-p tcp` / `-p udp` |
| Estadísticas | `-s` | `-s` |
| Direcciones y puertos numéricos | `-n` | `-n` |
| Proceso asociado | `-p` | `-o` (PID), `-b` (ejecutable) |

```bash
ss [opciones] [filtro]
ss -tl
```

```cmd
netstat -a
```

> [!note]
> En Windows `netstat -t` no filtra TCP (muestra el estado de descarga de las conexiones). En Linux, `netstat` (paquete *net-tools*) sí admite `-a -l -t -s`, pero está obsoleto frente a `ss`.

> [!info] Fuentes
> - [Microsoft Learn – netstat](https://learn.microsoft.com/es-es/windows-server/administration/windows-commands/netstat) y [ipconfig](https://learn.microsoft.com/es-es/windows-server/administration/windows-commands/ipconfig)
> - [ss(8) – man7.org](https://man7.org/linux/man-pages/man8/ss.8.html) e [ip-address(8)](https://man7.org/linux/man-pages/man8/ip-address.8.html)
> - [RFC 959 – FTP](https://www.rfc-editor.org/rfc/rfc959) y [RFC 6335 – Rangos de puertos](https://www.rfc-editor.org/rfc/rfc6335#section-6)
> - [IANA – Service Name and Port Number Registry](https://www.iana.org/assignments/service-names-port-numbers/)
