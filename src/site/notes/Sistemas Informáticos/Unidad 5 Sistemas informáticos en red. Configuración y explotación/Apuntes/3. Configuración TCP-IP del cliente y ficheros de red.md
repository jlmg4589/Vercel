# Unidad 5: Sistemas informáticos en red. Configuración y explotación

> [!abstract] Criterios que se trabajan
> **CE5A** (configuración del protocolo TCP/IP). Contenidos **BC5_1** (configuración estática y dinámica automática), **BC5_2** (ficheros de configuración de red), **BC5_5** (herramientas gráficas) y **BC5_8** (configuración de adaptadores en SO libres y propietarios).

La asignación de una dirección IP a un adaptador de red puede ser **estática** o **dinámica**.

## 3.1 Configuración estática

Se usa una **IP fija** para el host (no cambia con el tiempo). Ideal para **servidores** de Internet o equipos que deban mantener su IP para ofrecer servicios (impresión, HTTP, FTP…). La asigna **manualmente** el administrador en la configuración del adaptador.

### 3.1.1 Datos que hay que introducir

El administrador de red facilita los valores:

| Campo | Descripción |
| --- | --- |
| **Dirección IP** | Ver [[Sistemas Informáticos/Unidad 5 Sistemas informáticos en red. Configuración y explotación/Apuntes/2. Direccionamiento IPv4 e IPv6\|2. Direccionamiento IPv4 e IPv6]]. |
| **Máscara de subred** | Determina la porción de red y de host. |
| **Puerta de enlace predeterminada** (*gateway* por defecto) | Normalmente el **router** por el que se accede a Internet; también puede ser otro host que interconecte redes distintas. |
| **Servidor DNS preferido** | IP de un servidor DNS, que traduce nombres de dominio a IP (p. ej., `www.sintesis.com` → `193.70.32.179`). |
| **Servidor DNS alternativo** | Es recomendable indicar otro servidor DNS. |

> [!example] Servidores DNS públicos
> | Servicio | Direcciones |
> | --- | --- |
> | Google Public DNS | 8.8.8.8 y 8.8.4.4 |
> | OpenDNS | 208.67.222.222 y 208.67.220.220 |

### 3.1.2 Microsoft Windows (herramienta gráfica)

1. **Centro de redes y recursos compartidos** → **Cambiar opciones del adaptador** (*Conexiones de red*).
2. Abrir el adaptador Ethernet → **Propiedades**.
3. Seleccionar **Protocolo de Internet versión 4 (TCP/IPv4)** → **Propiedades**.
4. Marcar **Usar la siguiente dirección IP** (IP, máscara, puerta de enlace) y **Usar las siguientes direcciones de servidor DNS** (preferido y alternativo).

### 3.1.3 GNU/Linux: Ubuntu (herramienta gráfica)

1. **Configuración** → **Red**.
2. Pulsar la **rueda dentada** del adaptador.
3. Pestaña **IPv4** → opción **Manual** e introducir los datos.

## 3.2 Configuración dinámica (DHCP)

La IP **cambia con el tiempo**. La mayoría de equipos usan este método gracias al protocolo **DHCP**: un **servidor DHCP** proporciona a los **clientes DHCP** (hosts con esta opción habilitada en el adaptador) la configuración necesaria: IP, máscara, servidor DNS, puerta de enlace…

- El servidor DHCP permite establecer el **rango de direcciones asignables** (IP de inicio y fin), servidores DNS, *gateway* por defecto… Todos esos datos se trasladan a la configuración TCP/IP de los clientes.
- El resto de direcciones se reservan para **direccionamiento estático**.
- En el cliente, las propiedades de **TCP/IPv4** se mantienen en **automático** para obtener IP dinámica.

> [!note] Routers SoHo
> Los routers **SoHo** (*Small Office, Home Office*), los de casa u oficina, habilitan el servidor DHCP por defecto.

## 3.3 Ficheros de configuración de red

### 3.3.1 NetPlan (Ubuntu)

**NetPlan** es la herramienta de Ubuntu para gestionar la configuración de red desde **Ubuntu 17.10**, con la intención de sustituir la configuración clásica del archivo `/etc/network/interfaces`.

**1. Identificar las interfaces** del sistema:

```bash
ip a
sudo lshw -class network
```

El directorio `/etc/netplan/` alberga los ficheros de configuración. En Ubuntu Desktop:

| Fichero | Función |
| --- | --- |
| `01-network-manager-all.yaml` | Primera configuración. |
| `02-network-manager-all.yaml` | Segunda configuración (si existe). |
| … | Se aplican en el orden numérico de su nombre. |

**2. Editar el fichero** con privilegios de administrador, respetando los espacios de sangría (YAML):

```yaml
network:
  version: 2
  renderer: NetworkManager   # o networkd
  ethernets:
    NOMBRE_DISPOSITIVO:
      dhcp4: no              # yes = DHCP, no = estático
      addresses: [DIRECCION_IP/MASCARA]
      routes:
        - to: default
          via: PUERTA_DE_ENLACE
      nameservers:
        addresses: [DNS_1, DNS_2]
```

| Clave | Significado |
| --- | --- |
| `renderer` | Gestor de red: **NetworkManager** en escritorio, **networkd** en servidores. |
| `NOMBRE_DISPOSITIVO` | Nombre de la interfaz que se configura. |
| `dhcp4` | `yes` (DHCP) o `no` (estático). |
| `addresses` | IP en notación prefijo (CIDR). |
| `routes` | Puerta de enlace. |
| `nameservers` | IP de los servidores DNS. |

> [!note] Las claves van en minúscula
> La fuente escribe `Network:`, `Version:` y `Renderer:` con mayúscula inicial: es un error. YAML distingue mayúsculas y NetPlan solo reconoce las claves en minúscula (`network`, `version`, `renderer`…). Para `dhcp4` la documentación usa `true`/`false` (se aceptan también `yes`/`no`). Antes de `netplan apply` puede probarse la configuración con `sudo netplan try` (se revierte si no se confirma).

> [!info] Fuentes
> - [Netplan – YAML configuration reference](https://netplan.readthedocs.io/en/stable/netplan-yaml/)
> - [Netplan – netplan try](https://netplan.readthedocs.io/en/stable/netplan-try/)

> [!warning] Falta fuente: ejemplos de NetPlan
> Los ejemplos de configuración estática y dinámica de una interfaz Ethernet y el "ejemplo del proceso completo" son capturas no conservadas.

**3. Aplicar los cambios:**

```bash
sudo netplan apply
```

**4. Comprobar** las interfaces:

```bash
ip address show [interfaz]
ip a
```
