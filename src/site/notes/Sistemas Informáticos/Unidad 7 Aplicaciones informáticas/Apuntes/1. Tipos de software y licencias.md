# Unidad 7: Aplicaciones informáticas

> [!abstract] Resultado de aprendizaje

>
> Criterios de evaluación:
> a) Se ha clasificado software en función de su licencia y propósito.
> b) Se han analizado las necesidades específicas de software asociadas al uso de sistemas informáticos en diferentes entornos productivos.
> c) Se han realizado tareas de documentación mediante el uso de herramientas ofimáticas y de trabajo colaborativo.
> d) Se han utilizado sistemas de correo y mensajería electrónica.

> g) Se han utilizado herramientas de propósito general.

En esta unidad estudiamos las **aplicaciones informáticas** como herramientas para realizar tareas concretas: procesadores de texto, hojas de cálculo, antivirus, software de mantenimiento… Para que funcionen correctamente, cada aplicación especifica unos **requisitos** de hardware y de sistema operativo.

Además de las aplicaciones ofimáticas veremos las herramientas que usan servicios de Internet (correo electrónico, mensajería instantánea, transferencia de ficheros, computación y almacenamiento en la nube), las herramientas de seguridad y mantenimiento y, por último, una tarea básica en la empresa: **buscar y elaborar documentación técnica**.

## 1.1 Clasificación por licencia

Una **licencia de software** es el contrato entre el titular de los derechos (fabricante o autor) y el usuario que se asocia al programa cuando este lo adquiere u obtiene. En ella se fijan las condiciones de **uso, instalación, distribución, publicación y estudio** del software.

### 1.1.1 Software libre (*free software*)

Definido por la **Free Software Foundation (FSF)**: el usuario dispone de **cuatro libertades**:

| Libertad | Permite |
| :-: | --- |
| 0 | **Ejecutar** el programa como se desee, con cualquier propósito. |
| 1 | **Estudiar** cómo funciona y **cambiarlo** para adaptarlo a sus necesidades (requiere acceso al código fuente). |
| 2 | **Redistribuir copias** para ayudar a otros. |
| 3 | **Distribuir copias de sus versiones modificadas**, para que toda la comunidad se beneficie (requiere acceso al código fuente). |

> [!note] *Free* no significa gratis
> El software libre puede ser gratuito o de pago. La confusión viene de traducir el inglés *free* como "gratuito" en lugar de "libre" (*"free as in free speech, not as in free beer"*).

### 1.1.2 Software propietario o privativo

Es aquel cuyo uso, redistribución o modificación están **prohibidos o requieren autorización** del titular. Normalmente no se tiene acceso al código fuente.

### 1.1.3 Software con *copyleft*

El *copyleft* garantiza que el software, y **cualquier versión modificada o redistribuida**, siga siendo libre y se distribuya sin restricciones añadidas. Ejemplo de licencia: **GNU GPL**, usada por el **núcleo Linux**.

### 1.1.4 Software de dominio público

Software **sin derechos de autor** (sin *copyright*), porque el autor ha renunciado a ellos o han expirado. Si el código fuente es de dominio público es software libre **sin *copyleft***, de modo que alguien podría crear una versión derivada privativa.

### 1.1.5 Software sin *copyleft* (licencias permisivas)

Al contrario que el *copyleft*, las obras derivadas **no tienen por qué mantener la misma licencia**: se pueden integrar incluso en software privativo. Ofrecen gran flexibilidad. Ejemplos:

- **Licencia BSD:** sistemas operativos FreeBSD y NetBSD.
- **Licencia MIT:** Bitcoin Core.
- **Licencia Apache 2.0:** la mayor parte del espacio de usuario de Android (AOSP); el núcleo de Android sigue siendo GPL.

### 1.1.6 Mozilla Public License (MPL)

Está a medio camino entre la GPL y la BSD: es un ***copyleft* débil** (por archivo). Los **archivos con código MPL** (y sus modificaciones) deben seguir bajo MPL y, si se distribuyen, ofrecer su código fuente, pero se pueden combinar con otros archivos con licencia distinta (incluso privativa) en una obra mayor. Ejemplo: el navegador **Mozilla Firefox** y la suite LibreOffice.

### 1.1.7 Software libre frente a código abierto (*open source*)

Frente al software privativo están las licencias de software libre y las de código abierto. Ambas defienden una mayor libertad del software, pero el **software libre** está más orientado a la **ética** (habla de libertades) y el **código abierto** es más **pragmático**: la **Open Source Initiative (OSI)** exige que la licencia cumpla diez criterios (*Open Source Definition*):

1. Libre redistribución.
2. Inclusión del código fuente.
3. Se permiten modificaciones y obras derivadas en las mismas condiciones que el original.
4. Integridad del código fuente del autor (puede exigirse que las obras derivadas cambien de nombre o versión).
5. Sin discriminación de personas o grupos.
6. Sin discriminación de campos de actividad.
7. Los derechos se aplican a todos los que reciben el programa, sin licencias adicionales.
8. La licencia no debe ser específica de un producto.
9. La licencia no debe restringir otro software distribuido junto con el licenciado.
10. La licencia debe ser tecnológicamente neutral.

### 1.1.8 *Shareware* y *freeware*

Son formas de **distribución** para dar a conocer un producto. Normalmente el código fuente no está disponible, por lo que **no son software libre**:

- ***Shareware*:** versión con funciones limitadas o uso limitado en el tiempo; tras pagar, se usa con normalidad.
- ***Freeware*:** gratuito y sin límite de tiempo.

### 1.1.9 Licencias de software propietario: CLUF/EULA

En el software propietario (por ejemplo, Microsoft Windows) se acepta un **contrato de licencia de usuario final** (**CLUF**, en inglés *EULA*, *End-User License Agreement*). Habitualmente el usuario se compromete a:

- No copiar ni distribuir el software.
- Permitir que el propietario recopile cierta información del sistema (telemetría).
- Usar el producto **sin ser su dueño**: se adquiere un derecho de uso.

Canales de licencia de Microsoft:

- **OEM:** asociada al **equipo** con el que se vende; se activa al conectarse a Internet y no se puede trasladar a otro equipo.
- **Retail (comercial):** se compra aparte, independientemente del hardware. Es para **un único equipo** a la vez, pero se puede transferir a otro equipo si se cambia el hardware.
- **Licencias por volumen:** para medianas y grandes organizaciones; permiten activar muchos equipos (claves MAK o servidor KMS).

> [!tip] ¿Qué tipo de licencia tiene mi Windows?
> El método fiable es ejecutar en una consola (como administrador) el script de gestión de licencias:
> ```cmd
> slmgr /dli
> ```
> En la línea **Descripción** aparece el canal: `RETAIL`, `OEM_DM`/`OEM_COA`, `VOLUME_MAK`, `VOLUME_KMSCLIENT`…
> También se puede consultar el **Id. del producto** en *Configuración → Sistema → Información*: si contiene `OEM` es una licencia OEM. El comando `winver` solo muestra la versión y a quién está concedida la licencia (usuario u organización), no el canal.

> - LibreOffice se distribuye bajo **MPL 2.0** (con partes también bajo LGPLv3+) y Apache OpenOffice bajo **Apache License 2.0**.
>

## 1.2 Clasificación por propósito

- **Software base o de sistema:** actúa de intermediario, gestor o administrador entre el usuario y el hardware. Ej.: firmware BIOS/UEFI, sistemas operativos, controladores (*drivers*), utilidades de diagnóstico.
- **Software de desarrollo:** necesario para diseñar, desarrollar e implementar software de sistema o de aplicación. Ej.: editores, compiladores, depuradores y entornos de desarrollo integrados (**IDE**).
- **Software de aplicación:** orientado a tareas concretas del usuario final. Ej.: ofimática, software empresarial (ERP, CRM), diseño, seguridad, navegadores, juegos y asistentes de **IA generativa**.
